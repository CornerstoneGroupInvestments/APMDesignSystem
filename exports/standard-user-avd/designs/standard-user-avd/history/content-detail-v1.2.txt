H1 |1. Introduction
H2 |1.1 Purpose
P |This document provides the detailed technical design for the APM Standard User Standard Operating Environment (SOE) delivered on Azure Virtual Desktop (AVD), orchestrated by Nerdio Manager for Enterprise, managed by Microsoft Intune and Microsoft Entra ID, and deployed into the existing APM corporate tenant and Azure Enterprise-Scale Landing Zone (ESLZ).
P |The design extends the production Windows 11 laptop SOE into AVD as a second delivery channel. The SOE is one thing with two channels: a physical Entra-joined laptop, or a Windows 11 Enterprise multi-session host reached through the Windows App. The hardening standard, the Intune policy stack and the compliance position are the same in both channels, and every divergence is named in this document.
P |It traces business requirements to the architecture that meets them, records the design decisions and the options assessed for each, specifies the logical and physical architecture across the business, application, technology, information and cyber domains, and sets out the risk register, the APM Windows SOE Hardening Standard alignment, the availability model and the service management model.
P |The decision being asked for is approval to build the Standard User SOE on AVD as specified. Four positions a reviewer is most likely to challenge are argued in section 7 rather than left to be discovered: access from unmanaged personal devices, the three tenant Conditional Access policies this design requires to move from report-only to enforced, the absence of script enforcement in the inherited Application Control policy, and the security log workspace retention shortfall against APM's own 180-day non-functional requirement.
P |Configuration values, console paths and build steps are not in this document. They are specified in the companion Technical Configuration Document. Section references in this document point to headings in this document unless the companion document is named.

H1 |2. Overview
P |APM operates a mature Windows 11 laptop SOE: Entra-joined, Intune-managed, hardened under the APM Windows SOE Hardening Standard V3.0, with 748 controls across 11 Intune policies benchmarked against ASD Windows hardening guidance, the Microsoft Windows 11 security baseline and the Microsoft Edge security baseline v139, and App Control for Business in enforcement.
P |This design delivers that same SOE on Azure Virtual Desktop. Session hosts run Windows 11 Enterprise multi-session on a pooled host pool, orchestrated by Nerdio Manager for Enterprise, Entra-joined and Intune-enrolled so the same policy objects govern them. User state persists in FSLogix profile containers on Azure Files Premium authenticated with Microsoft Entra Kerberos, so no Active Directory Domain Services dependency is introduced.
P |The solution deploys into the existing APM corporate tenant and the existing Australia East landing zone. The AVD subscription and spoke virtual network are already provisioned in the landing zone address plan and already peered to the regional hub, so this design allocates subnets inside an existing CIDR rather than requesting a new one, and inherits the landing zone's forced-tunnel egress through the hub Palo Alto next-generation firewalls. No public IP address, no inbound port and no internet-facing infrastructure is created in the spoke.
P |Access from an unmanaged personal device is permitted only as a session, never as data on the device. A personal device runs the Windows App and reaches an AVD session; it cannot reach Microsoft 365 directly. That boundary is enforced by Conditional Access and by the host pool's device-redirection properties, and it depends on tenant policies that are currently report-only, which section 7 states plainly.
P |Nerdio audit and operational events, session host diagnostics, host pool connection events, Azure Files transactions and firewall logs all land in Microsoft Sentinel in the security subscription, alongside the Defender for Endpoint and Intune signals the laptop SOE already produces.

H2 |2.2 Guiding Principles
TBL|2400,6960
TH |**Principle**||**What it means in this design**
TR |One SOE, two channels||The session host inherits the same policy objects as the laptop, not a copy of them. A control is varied only where a multi-session host physically cannot carry it, and every variation is named in 7 with its compensating control
TR |Identity is the perimeter||Trust is anchored in Entra ID and evaluated per sign-in. The unmanaged endpoint is never trusted; the session host is the trusted compute environment
TR |Inherit the landing zone, do not fork it||The design consumes the existing AVD subscription, spoke virtual network, hub peering, forced-tunnel egress, central private DNS and platform RBAC. Where the landing zone has an open item, this design states it rather than working around it
TR |Modern management only||Entra join and Intune. No Active Directory Domain Services, no Group Policy, no on-premises management plane in the session host path
TR |No public ingress||Session traffic uses the Microsoft-managed reverse connect transport. No public IP address, inbound port or internet-facing endpoint exists in the spoke, consistent with the landing zone prohibition on public IPs outside the connectivity subscription
TR |The image is the unit of change||Session hosts are replaced, not patched in place. A versioned image in the Compute Gallery is both the deployment mechanism and the rollback control
TR |Data leaves as a session, never as a file||From an unmanaged endpoint, clipboard and drive redirection out of the session are closed. The session is the only place APM data is handled
TR |Observable from the first host||Diagnostic settings, Defender for Endpoint, Intune reporting and the Nerdio log export are configured during build, not retrofitted after go-live

H1 |3. Business Architecture
P |The Standard User SOE on AVD answers three business outcomes: reducing the cost and lead time of the staff endpoint, supporting flexible and bring-your-own-device working without allowing APM data onto a device APM does not manage, and shortening the time from a new starter being provisioned to being productive.
P |APM's current staff endpoint is a managed Windows 11 laptop. It delivers a hardened, RFFR-aligned desktop, and it carries a fixed cost per seat, a procurement and build lead time per starter, and a hardware refresh cycle that ties the workforce to a device replacement programme. A lost or stolen laptop is an incident with a data exposure question attached to it.
P |AVD reframes the staff desktop as a service reached from any compatible endpoint. The hardened environment is the same; where it runs changes. Cost moves from capital hardware to metered consumption that scales with concurrency. A new starter is productive as soon as their identity exists and their group membership is applied. A lost endpoint carries no APM data, because no APM data was ever written to it.
P |AVD is offered alongside the laptop SOE, not as a replacement. Staff who need persistent local compute, offline working, specialist peripherals or graphics acceleration remain on the laptop channel. Staff whose work is browser, Office and standard line-of-business applications are candidates for AVD. The choice is per session, not per person: a member of staff with a corporate laptop can also use AVD from home on a personal device.

TR |DR-019||How an AVD session prints||Approved - APM Digital lead||Client-side printer redirection from the endpoint. The user population is office and home-based staff on corporate endpoints, so the printers a user needs are already installed on and reachable from their own device: at an APM site, including a participant site, the endpoint is on the corporate network and holds the site printer queues; at home it holds the user's own printer. Redirection presents those queues inside the session, so the session host never needs a route to a printer and no hybrid connectivity, print server or cloud print service is introduced. Options assessed: (a) client-side printer redirection, selected, because it requires nothing that does not already exist and works identically at every site; (b) Universal Print, rejected as unnecessary once (a) holds, since it would add a connector per site, a licence and a new service to operate; (c) direct IP printing from the session host over hybrid connectivity to each site, rejected outright as an operational burden at site scale for no gain; (d) no printing, rejected against requirement 10. Redirection is enabled on the managed desktop only and disabled on the unmanaged desktop, because printing from a personal device is a path for content to leave the session (DR-013)||7; requirement 10

H1 |7. Cyber & Security Architecture
P |The security architecture inherits the laptop SOE baseline and extends it with the controls a multi-session, bring-your-own-device-capable virtual desktop requires. Four positions are argued openly here rather than left to be found in review: access from unmanaged devices, the Conditional Access enforcement changes this design depends on, the inherited application control gap, and the security log retention shortfall.
P |**RFFR and ASD position.** APM operates under the Workforce Australia and Inclusive Employment Australia Service Deeds, both requiring compliance with the Right Fit For Risk framework administered by DEWR, which is based on ISO/IEC 27001 and the ASD Information Security Manual. RFFR compliance is managed under APM's existing ISMS. The AVD channel's position rests on three facts. The session host is treated as an endpoint for control purposes, not as server infrastructure, so it inherits the endpoint hardening standard rather than a server baseline. Every control the laptop SOE evidences for RFFR is either applied identically on the session host or replaced by a named compensating control in the SOE alignment tables below. And the subscription's placement under the Controlled management group puts the workload inside the landing zone's RFFR-regulated archetype by construction.
P |The hardening standard the fleet inherits is the APM Windows SOE Hardening Standard V3.0: 748 controls across 11 Intune policies, benchmarked against ASD Windows hardening guidance, the Microsoft Windows 11 security baseline and the Microsoft Edge security baseline v139, of which 568 meet or exceed the benchmark, 171 are additional hardening beyond it, and 9 are recorded as partial with a reason. Per-policy control counts below are the standard's own. This design changes none of those figures for the laptop channel.
P |`[UNRECONCILED]` The standard names its Windows 11 benchmark version inconsistently: the cover sheet states "Microsoft Windows 11 v24H2 baseline" and the report sheet states "Microsoft security baseline, Windows 11 v23H2". Both are reproduced here without selection. The consequence for this design is that the benchmark version a session host is assessed against cannot be stated definitively, which matters at an RFFR assessment of the AVD channel because the assessor reads the version from the standard. Resolution sits with the standard's owner, the End User Computing Manager, and is requested before the pilot exit review. No control value in this design depends on which version is correct.
P |**Identity and access control.** Every user of this solution is an existing APM staff identity in the corporate tenant. No new identity type is introduced, no local account is created on a session host for a user, and no shared account exists. The session host itself holds a device identity in Entra ID, which is what the compliance policy and the device filters below evaluate.

H1 |8. Service Availability and Disaster Recovery
H2 |8.1 Business Service Tiering
P |The Standard User SOE on AVD is classified Tier 2. An extended outage stops work for every member of staff whose only channel is AVD, which affects APM's ability to meet its service deed obligations, but alternate work modes exist: staff who also hold a corporate laptop continue working on the laptop channel throughout.
P |The classification is more stringent than the Participant Kiosk, where an outage degrades a self-service facility, and less stringent than a Tier 1 revenue or statutory reporting system, because a channel outage is not a data loss and does not stop the organisation. Tier 2 targets 99.9 per cent availability, a four-hour recovery time objective and a 24-hour recovery point objective. The recovery point objective applies to the profile container, since it is the only user data this solution stores; mail and documents are in Microsoft 365 and carry their own objectives.

P |Two reporting outputs are produced for the service rather than for an incident. A monthly capacity and cost report covering concurrency, sessions per host, scale events and consumption, which feeds the capacity review in 9.1. And a compliance report covering session host compliance state, App Control events and Conditional Access blocked attempts, which is the standing evidence set for the RFFR alignment review.

H1 |Appendix B: Test Environment
H2 |B.1 Purpose, and what it cannot prove
P |A non-production environment is built before any production object is created, so the solution can be assembled, broken and corrected without a production user, a production policy or a production network object being touched. It is where the golden image is built, where a new Intune profile is first applied, where the redirection boundary and the unmanaged-device block are first exercised, and where image rollback is rehearsed rather than assumed.
P |Three planes are fully isolated, because they are subscription-scoped: Azure compute, network and storage. A test session host cannot reach the production profile share, cannot use the production route table, and cannot be affected by a change to a production network security group.
P |Two planes cannot be isolated, and stating this plainly is the point of this appendix. Microsoft Intune and Microsoft Entra Conditional Access are tenant-level services: there is one Intune tenant and one Conditional Access policy set, shared with production and with the laptop fleet. Isolation on those planes is by assignment, not by boundary. The hub Palo Alto firewalls and Microsoft Sentinel are also shared platform services. The consequence is carried as R-12: a change proven in the test environment is not thereby proven in production, and the production validation host pool (5.4.2) is the gate for what the test environment cannot reach.

H2 |B.6 What the test environment must prove
P |Each test has a pass criterion that is objectively true or false. All twelve pass before the production build begins, and the set is re-run in the test environment for every subsequent image version and every policy change.
TBL|620,3400,5340
TH |**ID**||**Test**||**Pass criterion**
TR |T-01||Provision a session host from the shared gallery image||The host joins Entra ID, enrols in Intune, appears in the test device group and reports compliant, with no manual step
TR |T-02||Apply the 11 inherited hardening policies||All 11 report as applied. The set of controls reporting not applicable matches the six variations in 7 and contains nothing else
TR |T-03||Sign in a test user||The profile container is created and mounted, and the desktop presents the published application set
TR |T-04||Remove the test user's permission on the profile share, then sign in||Sign-in fails. No temporary profile is created and no user data is written to the host. This is the fail-closed behaviour in 7 and it is proven by fault injection, not by reading the setting
TR |T-05||Sign in a second user concurrently to the same host||Microsoft 365 Apps activate for both users through shared computer activation, and neither session is refused
TR |T-06||Place a Teams call||The call reports as optimised, and processor use on the session host stays at idle levels during the call, showing media is handled by the endpoint
TR |T-07||From the managed desktop, copy text and a file into and out of the session||Clipboard and drive redirection both succeed
TR |T-08||From the unmanaged desktop, attempt the same||Clipboard and drive redirection both fail. Camera and microphone still work
TR |T-09||From a device that is neither compliant nor Entra-joined, attempt Outlook on the web, SharePoint, Teams web and Graph||All are blocked by `CA-210`. The Windows App to AVD still succeeds with multi-factor authentication under `CA-202`
TR |T-10||Reach a destination not on the named egress list from a session host, then a destination on it||The first is denied at the hub firewall and the denial is visible in the firewall log; the second succeeds. This proves the egress model rather than assuming it
TR |T-11||Run an unsigned test binary||App Control blocks execution, and the block appears in Defender for Endpoint
TR |T-12||Leave the pool idle past the session limits, then trigger scale-in||An idle session disconnects at 1 hour, a disconnected session signs out at 4 hours, the profile container dismounts, and the emptied host is removed by auto-scale
TR |T-13||Reimage a host to the previous gallery image version||The host returns to service on the previous version and a user signs in successfully. This is the rollback control in 8.2 and it is rehearsed here
TR |T-15||Sign in a test user on a session host carrying the complete inherited hardening policy set, with the production Conditional Access policies enforced against the test user group||The profile container mounts. This is the test that proves the storage application exclusion (7, R-13), the `CloudKerberosTicketRetrievalEnabled` setting and the `WinHttpAutoProxySvc` service state all hold together on a fully hardened host, and it is the reason a mount is tested on a hardened host rather than a clean one
TR |T-16||Inspect `WinHttpAutoProxySvc` on a session host after all eleven inherited policies have applied||The service is in the running state. If a baseline stops it, the variation is raised before the pilot rather than diagnosed as an intermittent profile fault during it
TR |T-17||Add a temporary tenant-wide Conditional Access policy in report-only that would capture the storage application, then sign in||Report-only evaluation shows the storage application matched, demonstrating that the tenant can reach it and therefore that the exclusion in 7 is doing real work. Removed immediately after the test
TR |T-14||Check the telemetry destinations||Host pool connection events, session host events, FSLogix mount events and Nerdio audit events are all queryable in the workspaces named in 9.2
END
P |T-04, T-08, T-09, T-10, T-13 and T-15 are the tests that prove a control rather than a feature. If time is constrained, they are the last to be cut, not the first. T-15 in particular cannot be substituted by T-03: a profile container that mounts on a clean host proves nothing about a hardened host under the production Conditional Access set.

H2 |B.8 Promotion path
P |A change moves in one direction through four gates, and cannot skip one.
NUM|Made in the test environment: a new image version, a T-ring Intune profile, a network security group or firewall rule, or a Conditional Access change scoped to the test user group
NUM|Proven in the test environment against the applicable tests in B.6
NUM|Applied to the production pilot ring: the P-ring policy object assigned to `sg-stc-dvc-avd-session-hosts-ring1`, or the new image version on the production validation host pool
NUM|Promoted to the production host pool by drain-mode reimaging or by extending the policy assignment to `sg-dyn-dvc-avd-session-hosts`
P |The one exception is a Conditional Access change, which has no image and no ring: it moves from report-only, to enforced against the test user group, to enforced against the entitlement group, and each step is a separate change record.
