H3 |4.6.2 Phase 2 - Autopilot and enrolment
NUM|**Confirm the Default Windows device platform restriction requires no change.** Intune admin centre > Devices > Enrol devices > Device platform restrictions > Default > Windows > Properties. Personally owned = Block does not prevent this fleet enrolling: enrolment through Windows Autopilot is one of the methods Intune authorises as a corporate enrolment, so an Autopilot-registered device satisfies the restriction. APM tenant state confirmed 18 August 2026: Windows (MDM) = Allow, Personally owned = Block, no minimum or maximum OS version set. Device manufacturer restrictions are not supported on Windows. Device limit restrictions do not apply to a userless enrolment, which carries no user to count against
NUM|**Confirm Userless enrolment status = Allowed on each device record.** Devices > Enrol devices > Windows Autopilot deployment program devices. This is a per-device property of the Autopilot record, exposed as UserlessEnrollmentStatus in Microsoft Graph, and not a policy evaluation. It takes one of three values: Allowed, Blocked, or Unknown for a record that has not yet enrolled. It changes to Blocked after a device has completed a self-deploying or pre-provisioning deployment and then been reset, which is an anti-reuse guard on that hardware record
NUM|**Where the status reads Blocked, select the device and choose Unblock** (available from Intune 2310). This returns the status to Allowed and permits a further userless enrolment without deleting the Autopilot record or re-importing the hardware hash. Deregistering the device and importing a fresh hash also clears it, but is not required. A device left Blocked fails during OOBE with error 80180014
NUM|**Operational consequence for the fleet.** The status changes to Blocked only where a device is reset after a completed self-deploying deployment, so routine operation does not trigger it: the inactivity restart and the session purge (12.1.5, 12.1.7) are restarts rather than resets and leave the Autopilot record untouched. The events that do trigger it are a rebuild following an App Control rollback (13.3.2), warranty replacement hardware that has been provisioned previously, a device recycled between sites, and any use of Autopilot Reset as a remediation
NUM|**Standing practice to keep the fleet provisionable.** Three measures, owned by Digital Operations:
TBL |2600,6760
TH |Measure||Detail
TR |Unblock before every rebuild||Applying Unblock is the first step of the device replacement runbook (13.3.1) and the App Control rollback runbook (13.3.2), performed before the device is wiped rather than after a failed OOBE. Deregistering the device and importing a fresh hardware hash achieves the same result and is the fallback where Unblock does not clear the status
TR |Confirm status before dispatch||A device is confirmed at Userless enrolment status = Allowed before it leaves the staging location, so no site receives hardware that cannot provision. For a batch, read the property from Microsoft Graph (deviceManagement/windowsAutopilotDeviceIdentities, property userlessEnrollmentStatus) rather than inspecting 540 portal rows; confirm which Graph endpoint version exposes the property in the tenant before relying on it
TR |Autopilot Reset is not a remediation for this fleet||A fault is remediated by policy, by a signed script, or by rebuild. Autopilot Reset sets the status to Blocked and gains nothing over a rebuild, because the device holds no user state to preserve
END

H3 |A.2.1 Detect-KioskSessionAccount.ps1 (detection script)
P |<#
P |.SYNOPSIS
P |    Detection script for the Participant Kiosk session account and Assigned Access state.
P |    Intune remediation pair: detect. Exit 0 = compliant, 1 = run remediation.
P |
P |.DESCRIPTION
P |    Compliant means all of:
P |      1. A local account named Kiosk-<SERIAL> exists (serial from Win32_BIOS, sanitised),
P |         is enabled, is a standard user (not in Administrators), and PasswordExpires = False.
P |      2. Winlogon is configured to auto-logon that account (AutoAdminLogon = 1,
P |         DefaultUserName matches; the password lives in the LSA DefaultPassword secret,
P |         which this script does not and cannot read back for comparison).
P |      3. Assigned Access configuration is applied (MDM_AssignedAccess.Configuration not empty)
P |         and names the same account.
P |
P |.NOTES
P |    Runs as SYSTEM, 64-bit. Sign with the APM code-signing certificate (SOE-02).
P |    Policy: CDG-W11-REM-Kiosk Session Account-P-1.0 (detection half).
P |#>
P |$ErrorActionPreference = 'Stop'
P |try {
P |    $serial = ((Get-CimInstance Win32_BIOS).SerialNumber -replace '[^A-Za-z0-9]', '').ToUpperInvariant()
P |    if (-not $serial) { Write-Output 'No BIOS serial'; exit 1 }
P |    $user = "Kiosk-$serial"
P |    if ($user.Length -gt 20) { $user = $user.Substring(0, 20) }   # SAM account name limit
P |
P |    $acct = Get-LocalUser -Name $user -ErrorAction SilentlyContinue
P |    if (-not $acct -or -not $acct.Enabled) { Write-Output "Account $user missing or disabled"; exit 1 }
P |    if ($acct.PasswordExpires) { Write-Output "$user has password expiry"; exit 1 }
P |    if (Get-LocalGroupMember -Group 'Administrators' -Member $user -ErrorAction SilentlyContinue) { Write-Output "$user is an administrator"; exit 1 }
P |
P |    $wl = Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon'
P |    if ($wl.AutoAdminLogon -ne '1' -or $wl.DefaultUserName -ne $user) { Write-Output 'Autologon not configured'; exit 1 }
P |    if ($wl.PSObject.Properties['DefaultPassword']) { Write-Output 'Cleartext DefaultPassword present - must be LSA secret only'; exit 1 }
P |
P |    $aa = Get-CimInstance -Namespace 'root\cimv2\mdm\dmmap' -ClassName 'MDM_AssignedAccess' -ErrorAction SilentlyContinue
P |    if (-not $aa -or -not $aa.Configuration) { Write-Output 'Assigned Access not applied'; exit 1 }
P |    $cfgXml = [System.Net.WebUtility]::HtmlDecode($aa.Configuration)
P |    if ($cfgXml -notmatch [regex]::Escape($user)) { Write-Output 'Assigned Access does not name the kiosk account'; exit 1 }
P |
P |    Write-Output "Compliant: $user, autologon set, Assigned Access applied"
P |    exit 0
P |}
P |catch { Write-Output "Detection error: $($_.Exception.Message)"; exit 1 }

H3 |A.2.2 Remediate-KioskSessionAccount.ps1 (remediation script)
P |<#
P |.SYNOPSIS
P |    Remediation script: creates the named kiosk session account Kiosk-<SERIAL>, configures
P |    automatic logon with a password nobody knows, and applies the multi-app Assigned Access
P |    configuration naming that account.
P |
P |.DESCRIPTION
P |    What it does, in order:
P |      1. Reads the BIOS serial and derives the account name Kiosk-<SERIAL> (sanitised,
P |         capped at the 20-character SAM limit).
P |      2. Creates the local standard user if missing. The password is 32 characters from a
P |         cryptographic RNG, generated in memory on this device. It is set on the account
P |         and written ONLY to the Winlogon LSA DefaultPassword secret, then discarded.
P |         It is never logged, never transmitted, never written to the registry in cleartext,
P |         and never known to any person. A local administrator (LAPS-gated) could extract

H2 |A.3 Configuring the Start menu and taskbar pins - click by click
P |StartPins and TaskbarLayout are both part of the same Assigned Access XML (A.1) - there is no separate Intune screen for them. Build them in this order, then fold the result into the Profile element before importing the XML in step 4.6.5.1.
NUM|**Find each app's real shortcut path.** On a reference (pilot-build) device, open File Explorer and navigate to `C:\ProgramData\Microsoft\Windows\Start Menu\Programs` (the all-users Start Menu folder, referenced as `%ALLUSERSPROFILE%\Microsoft\Windows\Start Menu\Programs` in the XML). Confirm the exact `.lnk` file name for Microsoft Edge, LibreOffice Writer/Calc/Impress, and each accessibility tool under the `Accessibility` subfolder - installer versions can rename or nest these
NUM|**Confirm the File Explorer shortcut separately.** File Explorer's shortcut lives in the per-user Start Menu folder, `%APPDATA%\Microsoft\Windows\Start Menu\Programs`, not the all-users folder - this is why its path in the XML differs from the others
NUM|**Confirm accessibility tool presence.** Narrator, Magnifier and On-Screen Keyboard shortcuts are present on every supported Windows 11 feature version; Voice access is newer and its shortcut name/presence varies by version. On the reference device, open Start and search "Voice access" - if no shortcut exists, note the app's AUMID instead (`Get-StartApps` in PowerShell lists installed app AUMIDs) and pin by AUMID in the JSON below rather than by `desktopAppLink`
NUM|**Build the StartPins JSON.** List every pin as one object in a `pinnedList` array, in the order they should appear on the Start layout - either `{"desktopAppLink":"<path to .lnk>"}` for a desktop shortcut or `{"packagedAppId":"<AUMID>"}` for a packaged app. Use the exact paths confirmed in steps 1-3
NUM|**Wrap the JSON in the StartPins element**, inside the `Profile`, using the `v5` namespace and a `CDATA` section so the JSON is not parsed as XML: `<v5:StartPins><![CDATA[{"pinnedList":[...]}]]></v5:StartPins>`. The full example, with all nine pins for this fleet, is in A.1
NUM|**Build the taskbar layout XML.** Inside a `LayoutModificationTemplate` root (namespaces `http://schemas.microsoft.com/Start/2014/LayoutModification` and `taskbar="http://schemas.microsoft.com/Start/2014/TaskbarLayout"`), add one `<taskbar:DesktopApp DesktopApplicationLinkPath="<path>" />` per pin, inside `CustomTaskbarLayoutCollection > defaultlayout:TaskbarLayout > TaskbarPinList`, in the order they should appear left to right

Also add `<Taskbar ShowTaskbar="true" />` alongside it so the taskbar itself is visible. Both are shown in full in A.1
NUM|**Validate on a pilot device before rollout.** Deploy the profile (step 4.6.5.1), sign the device in as Kiosk-[SERIAL], and visually confirm: Start opens showing exactly the nine pinned tiles in the set order, and the taskbar shows the same set of icons pinned in the set order with no extra Windows-default icons (Store, Mail, etc.) present. If a pin is missing, the shortcut path did not match the device's actual install location - re-check step 1 or 2 on that exact build, not the reference device
NUM|**If a pin still fails after re-checking the path**, pin the app by AUMID instead of `desktopAppLink` (`Get-StartApps` gives the AUMID) - more reliable across Windows 11 servicing updates than a hardcoded shortcut path
BQ |**FileExplorerNamespaceRestrictions block (A.1, a different part of the same XML, unrelated to StartPins/TaskbarLayout): see Appendix C.**

H3 |A.4.1 Install-KioskIdleWatchdog.ps1 (installer, runs once per device as SYSTEM)
P |<#
P |.SYNOPSIS
P |    Participant Kiosk inactivity watchdog installer.
P |    Copies the signed watchdog to C:\APM\PK\ and registers the scheduled task that restarts
P |    the device after 600 seconds with no keyboard or mouse input.
P |
P |.DESCRIPTION
P |    Runs once per device as SYSTEM. Performs:
P |      1. Copies Watch-KioskIdle.ps1 from this package to C:\APM\PK\Watch-KioskIdle.ps1.
P |      2. Verifies the copied file carries a valid Authenticode signature, and exits 1
P |         without registering the task if it does not.
P |      3. Sets read-only ACLs so the participant session cannot alter the watchdog.
P |      4. Registers the scheduled task APM-PK-IdleWatchdog: logon trigger, 30-second repeat,
P |         running in the interactive user context (not SYSTEM), so GetLastInputInfo returns
P |         that session's true input time.
P |
P |.NOTES
P |    Deploy as a Win32 application, NOT a platform script: the package must carry two files,
P |    this installer and the separately signed Watch-KioskIdle.ps1, because the scheduled task
P |    launches the watchdog with -ExecutionPolicy AllSigned and a watchdog generated on the
P |    device cannot be signed.
P |      Install command:    powershell.exe -NoProfile -ExecutionPolicy AllSigned -File .\Install-KioskIdleWatchdog.ps1
P |      Uninstall command:  powershell.exe -NoProfile -ExecutionPolicy AllSigned -Command "Unregister-ScheduledTask -TaskName 'APM-PK-IdleWatchdog' -Confirm:$false; Remove-Item 'C:\APM\PK\Watch-KioskIdle.ps1' -Force"
P |      Detection rule:     File - C:\APM\PK - Watch-KioskIdle.ps1 - File or folder exists
P |      Install behaviour:  System.  Device restart behaviour: No specific action.
P |    Both this installer and Watch-KioskIdle.ps1 signed with the APM code-signing certificate
P |    (SOE-02) before packaging. Policy: CDG-W11-REM-Idle Restart-P-1.0.
P |    Assignment: sg-dyn-dvc-cdg-participant-kiosk. Values per the Detailed Design, 4.3.2.
P |#>
P |$ErrorActionPreference = 'Stop'
P |
P |$dir = 'C:\APM\PK'
P |$watchdogPath = Join-Path $dir 'Watch-KioskIdle.ps1'

H3 |A.4.2 Watch-KioskIdle.ps1 (the watchdog, runs in the participant session)
P |Must be signed before packaging. The installer verifies the signature on the copied file and exits 1 without registering the scheduled task if it is not valid, so an unsigned watchdog fails visibly at install rather than silently at run time.
P |<#
P |.SYNOPSIS
P |    Participant Kiosk inactivity watchdog. Restarts the device after 600 seconds with no
P |    keyboard or mouse input in the participant session.
P |
P |.DESCRIPTION
P |    Runs in the interactive participant session (Kiosk-<SERIAL>), launched every 30 seconds
P |    by the scheduled task APM-PK-IdleWatchdog. Polls Win32 GetLastInputInfo, which returns
P |    the true input time only when called from the interactive session, not from SYSTEM.
P |
P |    Behaviour: arms on the first input event of a session so an untouched device does not
P |    restart in a loop, warns full-screen at 540 seconds with a live one-second countdown
P |    held on screen for the whole final 60, closes as soon as real input resumes, and at
P |    600 seconds runs shutdown /r /t 0 /f. The restart
P |    triggers CDG-W11-REM-Profile Purge-P-1.0.
P |
P |.NOTES
P |    MUST be signed with the APM code-signing certificate (SOE-02) BEFORE it is packaged.
P |    The scheduled task launches it with -ExecutionPolicy AllSigned, so an unsigned copy
P |    does not run and the ten-minute purge claimed on the participant wallpaper is not met.
P |    Deployed by Install-KioskIdleWatchdog.ps1, which copies this file to C:\APM\PK\ and
P |    refuses to continue if its signature is not valid.
P |    Values per the Detailed Design, 4.3.2. Runs as the interactive user, 64-bit.
P |#>
P |$ErrorActionPreference = 'SilentlyContinue'
P |Add-Type -TypeDefinition @"
P |using System;
P |using System.Runtime.InteropServices;
P |public static class Idle {
P |    [StructLayout(LayoutKind.Sequential)] struct LASTINPUTINFO { public uint cbSize; public uint dwTime; }
P |    [DllImport("user32.dll")] static extern bool GetLastInputInfo(ref LASTINPUTINFO plii);
P |    [DllImport("kernel32.dll")] static extern uint GetTickCount();
P |    public static uint Seconds() {
P |        LASTINPUTINFO lii = new LASTINPUTINFO();
P |        lii.cbSize = (uint)Marshal.SizeOf(lii);
P |        if (!GetLastInputInfo(ref lii)) return 0;
P |        return (GetTickCount() - lii.dwTime) / 1000;
P |    }
P |}
P |"@
P |$script:thresholdSeconds = 600
P |$script:warnAtSeconds    = 540
P |$armFlag = Join-Path $env:TEMP 'apm-pk-idle-armed'

P |$idle = [Idle]::Seconds()
P |
P |# Arm on the first input event of a session: an untouched device must not restart in a loop
P |if (-not (Test-Path $armFlag)) {
P |    if ($idle -lt 30) { New-Item -Path $armFlag -ItemType File -Force | Out-Null }
P |    return
P |}
P |
P |if ($idle -ge $script:thresholdSeconds) {
P |    Remove-Item $armFlag -Force -ErrorAction SilentlyContinue
P |    shutdown /r /t 0 /f
P |    return
P |}
P |
P |if ($idle -ge $script:warnAtSeconds) {
P |    Add-Type -AssemblyName System.Windows.Forms
P |    Add-Type -AssemblyName System.Drawing
P |    $form = New-Object System.Windows.Forms.Form
P |    $form.FormBorderStyle = 'None'
P |    $form.WindowState = 'Maximized'
P |    $form.TopMost = $true
P |    $form.BackColor = [System.Drawing.Color]::FromArgb(31,45,88)
P |    $label = New-Object System.Windows.Forms.Label
P |    $label.AutoSize = $false
P |    $label.Dock = 'Fill'
P |    $label.TextAlign = 'MiddleCenter'
P |    $label.ForeColor = [System.Drawing.Color]::White

H3 |A.5.1 Install-KioskSessionPurge.ps1 (installer, runs once per device as SYSTEM)
P |<#
P |.SYNOPSIS
P |    Participant Kiosk session purge installer.
P |    Copies the signed purge script to C:\APM\PK\ and registers it to run at shutdown and
P |    again at startup (layers 2 and 3 of the three-layer purge, Detailed Design 6.4).
P |
P |.DESCRIPTION
P |    Runs once per device as SYSTEM. Performs:
P |      1. Copies Invoke-KioskSessionPurge.ps1 from this package to C:\APM\PK\.
P |      2. Verifies the copied file carries a valid Authenticode signature, and exits 1
P |         without registering anything if it does not.
P |      3. Sets read-only ACLs so the participant session cannot alter or delete the script.
P |      4. Registers the STARTUP pass as scheduled task APM-PK-PurgeStartup: AtStartup
P |         trigger, SYSTEM, highest privileges. This is the pass that removes a profile the
P |         shutdown pass could not, because it was still loaded.
P |      5. Registers the SHUTDOWN pass as a local Group Policy shutdown script, which is the
P |         only mechanism Windows waits for during shutdown. Task Scheduler has no shutdown
P |         trigger, so a scheduled task cannot serve here.
P |
P |.NOTES
P |    Deploy as a Win32 application, NOT a platform script: an Intune platform script runs
P |    once when Intune delivers it and has no shutdown hook, so a platform script alone would
P |    never produce a shutdown pass at all.
P |      Install command:    powershell.exe -NoProfile -ExecutionPolicy AllSigned -File .\Install-KioskSessionPurge.ps1
P |      Uninstall command:  powershell.exe -NoProfile -ExecutionPolicy AllSigned -File .\Install-KioskSessionPurge.ps1 -Uninstall
P |                          (removes the startup task, both script copies, the [Shutdown] entry
P |                           from psscripts.ini and the Scripts CSE from gpt.ini, then refreshes
P |                           policy - deleting the script file alone leaves Windows trying to run
P |                           a missing shutdown script on every restart)
P |      Detection rule:     File - C:\APM\PK - Invoke-KioskSessionPurge.ps1 - File or folder exists
P |      Install behaviour:  System.  Device restart behaviour: No specific action.
P |    Both this installer and Invoke-KioskSessionPurge.ps1 signed with the APM code-signing
P |    certificate (SOE-02) before packaging. Policy: CDG-W11-REM-Profile Purge-P-1.0.
P |    Assignment: sg-dyn-dvc-cdg-participant-kiosk.
P |    The shutdown script timeout is 600 seconds by default, far longer than a purge pass takes.
P |#>
P |[CmdletBinding()]
P |param([switch]$Uninstall)
P |
P |$ErrorActionPreference = 'Stop'
P |
P |$dir = 'C:\APM\PK'
P |$scriptName = 'Invoke-KioskSessionPurge.ps1'
P |$purgePath = Join-Path $dir $scriptName
P |$taskName = 'APM-PK-PurgeStartup'
P |$source = Join-Path $PSScriptRoot $scriptName
P |$gpRoot = 'C:\Windows\System32\GroupPolicy'
P |$gpShutdown = Join-Path $gpRoot 'Machine\Scripts\Shutdown'
P |
P |if (-not (Test-Path $dir)) { New-Item -Path $dir -ItemType Directory -Force | Out-Null }
P |
P |# ---- 0. uninstall: undo everything install registered ------------------------
P |# Removing the script file alone is not enough. The [Shutdown] entry in psscripts.ini and the
P |# Scripts client-side extension in gpt.ini survive, so Windows keeps trying to run a script
P |# that is no longer there and logs a failure on every restart.
P |if ($Uninstall) {
P |    Unregister-ScheduledTask -TaskName $taskName -Confirm:$false -ErrorAction SilentlyContinue
P |    Remove-Item (Join-Path $gpShutdown $scriptName) -Force -ErrorAction SilentlyContinue
P |    Remove-Item $purgePath -Force -ErrorAction SilentlyContinue
P |
P |    $iniPath = Join-Path $gpRoot 'Machine\Scripts\psscripts.ini'
P |    if (Test-Path $iniPath) {
P |        $keep = Get-Content $iniPath | Where-Object { $_ -notmatch [regex]::Escape($scriptName) -and $_ -notmatch '^\s*0Parameters\s*=' }
P |        if ($keep -join '' -match '\S') { Set-Content -Path $iniPath -Value $keep -Encoding Unicode -Force }
P |        else { Remove-Item $iniPath -Force -ErrorAction SilentlyContinue }
P |    }
P |
P |    # Bump gpt.ini so the local policy engine reprocesses and drops the shutdown script
P |    $gptPath = Join-Path $gpRoot 'gpt.ini'
P |    if (Test-Path $gptPath) {
P |        $v = 1
P |        foreach ($line in (Get-Content $gptPath)) { if ($line -match '^\s*Version\s*=\s*(\d+)') { $v = [int]$matches[1] + 1 } }
P |        $lines = @()
P |        foreach ($line in (Get-Content $gptPath)) {
P |            if ($line -match '^\s*Version\s*=') { $lines += ('Version=' + $v) } else { $lines += $line }
P |        }
P |        Set-Content -Path $gptPath -Value $lines -Encoding ASCII -Force
P |    }
P |
P |    Start-Process -FilePath 'gpupdate.exe' -ArgumentList '/target:computer /force' -Wait -WindowStyle Hidden
P |    Write-Output 'Uninstalled: startup task, both script copies, psscripts.ini entry and policy refreshed'
P |    exit 0
P |}
P |
P |# ---- 1. copy the signed purge script from the package -----------------------
P |if (-not (Test-Path $source)) {
P |    Write-Output "FAILED: $scriptName not found beside this installer. Package both files in the same .intunewin."
P |    exit 1
P |}
P |Copy-Item -Path $source -Destination $purgePath -Force
P |
P |# ---- 2. verify the signature before registering anything --------------------
P |$sig = Get-AuthenticodeSignature -FilePath $purgePath
P |if ($sig.Status -ne 'Valid') {
P |    Write-Output "FAILED: $scriptName signature status is $($sig.Status), not Valid. Sign the file with the APM code-signing certificate and repackage."
P |    Remove-Item $purgePath -Force -ErrorAction SilentlyContinue
P |    exit 1
P |}
P |Write-Output "Purge script signature valid: $($sig.SignerCertificate.Subject)"
P |
P |# ---- 3. read-only ACLs ------------------------------------------------------
P |$acl = Get-Acl $purgePath
P |$acl.SetAccessRuleProtection($true, $false)
P |$acl.Access | ForEach-Object { [void]$acl.RemoveAccessRule($_) }
P |foreach ($id in @('NT AUTHORITY\SYSTEM', 'BUILTIN\Administrators')) {
P |    $acl.AddAccessRule((New-Object System.Security.AccessControl.FileSystemAccessRule($id, 'FullControl', 'Allow')))
P |}
P |$acl.AddAccessRule((New-Object System.Security.AccessControl.FileSystemAccessRule('BUILTIN\Users', 'ReadAndExecute', 'Allow')))
P |Set-Acl -Path $purgePath -AclObject $acl
P |Write-Output "ACLs set: SYSTEM and Administrators full control, Users read and execute"
P |
P |# ---- 4. startup pass: scheduled task, SYSTEM, AtStartup ---------------------
P |Unregister-ScheduledTask -TaskName $taskName -Confirm:$false -ErrorAction SilentlyContinue
P |$argString = "-NoProfile -WindowStyle Hidden -ExecutionPolicy AllSigned -File " + [char]34 + $purgePath + [char]34
P |$action = New-ScheduledTaskAction -Execute 'powershell.exe' -Argument $argString
P |$trigger = New-ScheduledTaskTrigger -AtStartup
P |$principal = New-ScheduledTaskPrincipal -UserId 'NT AUTHORITY\SYSTEM' -LogonType ServiceAccount -RunLevel Highest
P |$settings = New-ScheduledTaskSettingsSet -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries -StartWhenAvailable -MultipleInstances IgnoreNew -ExecutionTimeLimit (New-TimeSpan -Minutes 10)
P |Register-ScheduledTask -TaskName $taskName -Action $action -Trigger $trigger -Principal $principal -Settings $settings -Force | Out-Null
P |Write-Output "Scheduled task $taskName registered - AtStartup, SYSTEM"
P |
P |# ---- 5. shutdown pass: local Group Policy shutdown script -------------------
P |if (-not (Test-Path $gpShutdown)) { New-Item -Path $gpShutdown -ItemType Directory -Force | Out-Null }
P |Copy-Item -Path $source -Destination (Join-Path $gpShutdown $scriptName) -Force
P |
P |# psscripts.ini is the PowerShell shutdown/startup script register (scripts.ini is cmd only)
P |$iniPath = Join-Path $gpRoot 'Machine\Scripts\psscripts.ini'
P |$ini = @(
P |    '[ShutdownPSScriptOrder]',
P |    'StartExecutePSFirst=true',
P |    '[Shutdown]',
P |    ('0CmdLine=' + $scriptName),
P |    '0Parameters='
P |)
P |Set-Content -Path $iniPath -Value $ini -Encoding Unicode -Force
P |(Get-Item $iniPath).Attributes = 'Hidden'
P |
P |# gpt.ini must name the Scripts client-side extension and carry a non-zero, incremented
P |# Version, or the local policy engine does not process the shutdown script at all
P |$gptPath = Join-Path $gpRoot 'gpt.ini'
P |$cse = '[{42B5FAAE-6053-11D2-9CF6-0060B0EC3D80}{40B6664F-4972-11D1-A7CA-0000F87571E3}]'
P |$version = 1
P |$existingCse = ''
P |if (Test-Path $gptPath) {
P |    foreach ($line in (Get-Content $gptPath)) {
P |        if ($line -match '^\s*Version\s*=\s*(\d+)') { $version = [int]$matches[1] + 1 }
P |        if ($line -match '^\s*gPCMachineExtensionNames\s*=\s*(.*)$') { $existingCse = $matches[1].Trim() }
P |    }
P |}
P |if ($existingCse -and $existingCse -notlike "*42B5FAAE-6053-11D2-9CF6-0060B0EC3D80*") { $cse = $existingCse + $cse }
P |elseif ($existingCse) { $cse = $existingCse }
P |Set-Content -Path $gptPath -Value @('[General]', ('gPCMachineExtensionNames=' + $cse), ('Version=' + $version)) -Encoding ASCII -Force
P |Write-Output "Local Group Policy shutdown script registered, gpt.ini Version=$version"
P |
P |Start-Process -FilePath 'gpupdate.exe' -ArgumentList '/target:computer /force' -Wait -WindowStyle Hidden
P |Write-Output "Machine policy refreshed - shutdown and startup purge passes both active"
P |exit 0

H3 |A.5.2 Invoke-KioskSessionPurge.ps1 (the purge, runs at shutdown and at startup as SYSTEM)
P |<#
P |.SYNOPSIS
P |    Participant Kiosk session purge. Deletes the participant profile and residual session
P |    data. Registered to run at shutdown and again at startup (layers 2 and 3 of the
P |    three-layer purge, Detailed Design 6.4).
P |
P |.DESCRIPTION
P |    Deletes, in order:
P |      1. Every local profile whose account name starts with "Kiosk-" via the Win32_UserProfile
P |         CIM class (the supported deletion path - removes the profile directory AND its
P |         registry hive and ProfileList entry, which rmdir alone does not).
P |      2. C:\Users\Public\Downloads contents.
P |      3. C:\Windows\Temp contents.
P |      4. The print spool directory contents (C:\Windows\System32\spool\PRINTERS).
P |    Never blocks shutdown: every step is wrapped, failures are logged and swallowed.
P |    Safe to run repeatedly and safe to run at startup, before the session account signs in.
P |
P |.NOTES
P |    Runs as SYSTEM, 64-bit. Sign with the APM code-signing certificate (SOE-02).
P |    Policy: CDG-W11-REM-Profile Purge-P-1.0. Assignment: sg-dyn-dvc-cdg-participant-kiosk.
P |    Deploy twice: as a shutdown script and as a startup task. The ADMX setting "Delete user
P |    profiles older than a specified number of days on system restart" = 0 is the third layer.
P |#>
P |$ErrorActionPreference = 'Continue'
P |$log = 'C:\APM\PK\purge.log'
P |$logDir = Split-Path $log -Parent
P |if (-not (Test-Path $logDir)) { New-Item -Path $logDir -ItemType Directory -Force | Out-Null }
P |function Write-Log($msg) {
P |    $line = (Get-Date -Format o) + "  " + $msg
P |    Add-Content -Path $log -Value $line -ErrorAction SilentlyContinue
P |    Write-Output $msg
P |}
P |
P |# ---- 1. participant profiles -------------------------------------------------
P |try {
P |    $profiles = Get-CimInstance -ClassName Win32_UserProfile -ErrorAction Stop |
P |        Where-Object { $_.LocalPath -and (Split-Path $_.LocalPath -Leaf) -like 'Kiosk-*' -and -not $_.Special -and -not $_.Loaded }
P |    if (-not $profiles) { Write-Log 'No unloaded Kiosk-* profile present' }
P |    foreach ($p in $profiles) {
P |        try {
P |            Remove-CimInstance -InputObject $p -ErrorAction Stop
P |            Write-Log ("Deleted profile " + $p.LocalPath)
P |        } catch { Write-Log ("Profile delete failed for " + $p.LocalPath + " - " + $_.Exception.Message) }
P |    }
P |    $loaded = Get-CimInstance -ClassName Win32_UserProfile -ErrorAction SilentlyContinue |
P |        Where-Object { $_.LocalPath -and (Split-Path $_.LocalPath -Leaf) -like 'Kiosk-*' -and $_.Loaded }
P |    foreach ($p in $loaded) { Write-Log ("Profile still loaded, will be removed by the startup pass: " + $p.LocalPath) }
P |} catch { Write-Log ("Profile enumeration failed - " + $_.Exception.Message) }
P |
P |# ---- 2-4. residual locations -------------------------------------------------
P |$targets = @(
P |    'C:\Users\Public\Downloads',
P |    'C:\Windows\Temp',
P |    'C:\Windows\System32\spool\PRINTERS'
P |)
P |foreach ($t in $targets) {
P |    try {
P |        if (Test-Path $t) {
P |            Get-ChildItem -Path $t -Force -ErrorAction SilentlyContinue |
P |                Remove-Item -Recurse -Force -ErrorAction SilentlyContinue
P |            Write-Log ("Cleared " + $t)
P |        }
P |    } catch { Write-Log ("Clear failed for " + $t + " - " + $_.Exception.Message) }
P |}
P |
P |Write-Log 'Purge pass complete'
P |exit 0

H2 |A.8 App Control (WDAC) Policy Authoring Command Sequence
P |The policy XML cannot be shipped pre-built: its rules reference the real signer certificates on the binaries as installed, so it must be generated on a reference device that already has the fleet's exact application set. Build it once, on a device that has completed Phases 5 and 6, then reuse the resulting XML for every device. Run every command in an elevated 64-bit PowerShell session.
H3 |A.8.1 Prepare the reference device
NUM|Provision a device through Autopilot (Phase 2) and let it complete all of Phase 5 and Phase 6, so Edge, LibreOffice, the Zscaler Client Connector and TeamViewer are all installed at the exact versions the fleet will run
NUM|Confirm nothing else is installed. Any binary present on the reference device may end up trusted by the generated policy
H3 |A.8.2 Generate the base policy from the reference device
P |`$policy = 'C:\APM\PK\CDG-W11-SEC-AppControl.xml'`
P |`New-CIPolicy -Level Publisher -Fallback Hash -FilePath $policy -UserPEs -ScanPath 'C:\Program Files' -ScanPath 'C:\Program Files (x86)' -ScanPath 'C:\Windows' -OmitPaths 'C:\Windows\Temp','C:\Users' -MultiplePolicyFormat -Verbose`
P |`-Level Publisher` produces publisher rules keyed on the signing certificate, so a signed vendor update continues to run without a policy change. `-Fallback Hash` covers any unsigned binary found during the scan - review every hash rule the scan produces and remove any that should not be trusted rather than accepting them silently. `-UserPEs` includes user-mode executables and DLLs (required for UMCI). `-MultiplePolicyFormat` produces a policy that can coexist with the Windows base policy.
H3 |A.8.3 Set the policy identity and rule options
P |`Set-CIPolicyIdInfo -FilePath $policy -PolicyName 'CDG-W11-SEC-AppControl Enforced-P-1.0' -PolicyId 'CDG-W11-PK-1.0' -ResetPolicyID`
P |`Set-CIPolicyVersion -FilePath $policy -Version '1.0.0.0'`
P |Record the PolicyID that `-ResetPolicyID` returns. It is the `{PolicyGUID}` in the OMA-URI path (12.1.3) and in the .cip filename.
TBL |2600,3200,3560
TH |Rule option||Command||Result
TR |Enabled: UMCI||`Set-RuleOption -FilePath $policy -Option 0`||Applies control to user-mode applications and DLLs
TR |Enabled: Inherit Default Policy||`Set-RuleOption -FilePath $policy -Option 5`||Inherits the Microsoft default trusted rules
TR |Required: Enforce Store Applications||`Set-RuleOption -FilePath $policy -Option 8`||Store applications in scope
TR |Enabled: Revoked Expired As Unsigned||`Set-RuleOption -FilePath $policy -Option 15`||Revoked or expired signatures treated as unsigned
TR |Enabled: Boot Audit On Failure||`Set-RuleOption -FilePath $policy -Option 10`||Degrades to audit rather than failing to boot
TR |Enabled: Update Policy No Reboot||`Set-RuleOption -FilePath $policy -Option 16`||A signed policy update applies without a restart
TR |**Disabled: Script Enforcement**||`Set-RuleOption -FilePath $policy -Option 11 -Delete`||Removes the option, which **enables** script enforcement. This is the tightening in 12.1.3 - deleting option 11 turns script control ON
TR |**Disabled: Unsigned System Integrity Policy**||`Set-RuleOption -FilePath $policy -Option 6 -Delete`||Removes the option, so only signed policies are accepted. Do this **last**, and only after A.8.5 has confirmed the signing certificate is in UpdatePolicySigners
END
P |Verify the resulting option set before signing: `Get-Content $policy | Select-String '<Option>'`. The audit-mode variant is the same file with `Set-RuleOption -FilePath $auditPolicy -Option 3` (Enabled: Audit Mode) added and option 6 left in place, saved under the name CDG-W11-SEC-AppControl Audit-T-1.0.
H3 |A.8.4 Remove anything the scan trusted that this fleet should not
P |Open the XML and confirm the `<Signers>` section resolves to the six publishers in 12.1.3 and nothing else: Microsoft, The Document Foundation, Zscaler Inc., TeamViewer, Dell and Patch My PC LLC. Delete any other signer or file rule the scan produced. Confirm no `<FileRules>` entry grants a path-based allow under C:\Users or C:\Windows\Temp.
P |TeamViewer is pinned to the deployed major version deliberately (12.1.3): keep its rule at the version-bounded publisher rule the scan generated rather than widening it, so a TeamViewer upgrade is a controlled policy change.
H3 |A.8.5 Add the signing certificate, then convert and sign
P |`Add-SignerRule -FilePath $policy -CertificatePath 'C:\APM\PK\apm-codesigning.cer' -Update -Supplemental:$false`
P |`-Update` writes the certificate into **UpdatePolicySigners**, which is what allows a future policy signed by the same certificate to replace this one. Without it the policy is permanent on every device it reaches, recoverable only by reimaging.
P |`ConvertFrom-CIPolicy -XmlFilePath $policy -BinaryFilePath 'C:\APM\PK\{PolicyGUID}.cip'`
P |Sign the resulting .cip with the APM code-signing certificate (SOE-02) using signtool, in the same way the estate signs its own policy. The signed .cip is the artefact uploaded to Intune.
H3 |A.8.6 Produce the rollback policy at the same time
P |Repeat A.8.3 with `Set-RuleOption -FilePath $rollbackPolicy -Option 3` (Audit Mode) and the same PolicyID, version 1.0.0.1, then convert and sign it. Hold this signed .cip in escrow with the certificate before the enforced policy is ever assigned (12.1.3, 13.3.2). It is the only route back from a bad enforced policy without reimaging, and test T-21 proves it works before national rollout.
H3 |A.8.7 Deploy
P |Audit policy: **Intune admin centre > Endpoint security > App Control for Business**, upload the unsigned audit XML, assign to sg-stc-dvc-cdg-participant-kiosk-ring1.
P |Enforced policy: **Devices > Configuration profiles > Create > Windows 10 and later > Templates > Custom**, OMA-URI `./Vendor/MSFT/ApplicationControl/Policies/{PolicyGUID}/Policy`, Data type **Base64 (file)**, upload the signed .cip. Assign to sg-dyn-dvc-cdg-participant-kiosk only after pilot validation passes (Phase 9).
H1 |Appendix C - Assigned Access XML Namespace Reference
P |`AllowedNamespace` is an element of the `rs5` (201810/config) namespace; `AllowRemovableDrives` and `NoRestriction` are `v3` (2020/config) elements (Microsoft Learn, Assigned Access configuration file / XSD). The XML in Appendix A uses these namespaces correctly.
P |`FileExplorerNamespaceRestrictions` enforcement on Windows 11 is inconsistent after cumulative updates KB5071430/KB5068861 (Microsoft Q&amp;A). Fallback if it does not hold on the target build: `<v3:NoRestriction />` combined with the App Control and Assigned Access AllowedApps restrictions as compensating controls. Test T-06 validates File Explorer scoping on the target feature version.
