H1 |2. Overview
H2 |2.1 Scope
P |**In scope**
P |• Physical Participant Kiosk provisioning and configuration: Dell hardware, Windows 11 Enterprise, Autopilot self-deploying enrolment into the existing APM corporate tenant, creating a device object only
P |• A named local session account (Kiosk-[SERIAL]) created on-device and signed in automatically, with no participant credential and no sign-in step
P |• Multi-app Assigned Access restricted experience: Microsoft Edge, LibreOffice, File Explorer scoped to Downloads, Desktop and removable drives, Zscaler tray, TeamViewer, with LibreOffice configuration locked by policy
P |• Device-based licensing only: Intune device licence, Windows 11 Enterprise E5, Defender for Endpoint P2
P |• Conditional Access, browser and web-filtering controls that prevent any Microsoft 365 sign-in from a Participant Kiosk
P |• Session hygiene: ten-minute inactivity sign-out and restart, with a full purge of participant data on every restart
P |• USB storage access for participants, and Zscaler web filtering and logging with local breakout from the device
P |• APM Windows SOE Hardening Standard inheritance, Edge CIS Level 2 hardening and the ISM Windows 11 baseline at device scope, with RFFR compliance alignment
P |**Out of scope**
P |• Standard User SOE, Developer SOE, Privileged Access and ES take-home device designs (separate documents)
P |• Network infrastructure and site cabling, and printer hardware procurement and physical placement
P |• Printing from Participant Kiosks, and any Microsoft 365 service access from a Participant Kiosk
P |• End-user training material and laminated instruction sheets (operational deliverable)
P |• RFFR formal accreditation audit. This document supports the ISMS; it does not constitute it
P |• Decommissioning of the retired kiosk components, raised as a separate change request ([[9.1]])
H2 |2.2 Guiding Principles
TBL|1416,7944
TH |**ID**||**Principle**
TR |Zero Trust||The device is the only identity. It is Entra-joined, Intune-managed and continuously assessed against a compliance policy. No corporate identity can authenticate from it: Conditional Access blocks every APM account on Participant Kiosk hardware.
TR |Ephemeral by Default||No participant data persists beyond the session. Edge browsing data never reaches the disk, downloads live only inside the profile, and the profile is purged on every restart.
TR |Least Privilege||The participant runs as a standard local account with Edge, LibreOffice and File Explorer scoped to Downloads, Desktop and removable drives. No settings, command prompt, task manager, installation or cloud sign-in.
TR |Simplicity||The end-user experience is frictionless. The device powers on directly into the participant session. There is no username, no password and no credential displayed anywhere.
TR |Compliance||The architecture meets RFFR requirements for the handling of participant personal information, aligning with ISO 27001 and the ASD ISM, and inherits the APM Windows SOE Hardening Standard V3.0.
END

H1 |3. Business Architecture
H2 |3.2 Business Reference architecture
P |The solution answers three business outcomes: consistent data privacy across all sites, standardised device management at scale, and RFFR compliance under the Workforce Australia and Inclusive Employment Australia Service Deeds.
P |Two business changes follow. Participants do not sign in, which removes credential handling from a public device and removes the risk of one participant using another's session. Documents are created in LibreOffice on the device rather than a browser-based Office suite, so no participant holds a Microsoft identity and every document stays on the participant's own media.

H1 |6. Information & Data Architecture
H2 |6.1 Information Model
P |The solution introduces no persistent data store: no cloud store, no mailbox, no OneDrive, no server-side profile. Data exists transiently on the device during a session, and on the participant's own USB media if they save it there. A session carries participant input (resumes, cover letters, applications, form submissions), browser data held in memory, application data in the local profile, and device telemetry from Intune, Defender and Zscaler. Absent by design: participant accounts, sign-in records, mailboxes, cloud documents, and directory objects naming a member of the public. The only identity in the system is the device.
P |A session begins when the device powers on and the session account signs in. It ends when the device restarts, either from the inactivity watchdog or a manual restart. Nothing carries from one session to the next. Figure 3 places the controls on the session timeline.

P |APM operates under the Workforce Australia and Inclusive Employment Australia Service Deeds. P |**Identity and access control.** The fleet has no cloud user identity. The participant session runs as a local account that Windows creates, credentials and signs in on its own behalf. The device authenticates to Entra ID; the person using it authenticates to nothing.

H2 |8.2 Disaster recovery & Resilience
P |The architecture is stateless, and recovery follows from that:
B |No persistent data. Nothing to recover: every session starts from clean device state
B |No cloud identity. No account to restore, no password to reissue, no directory dependency for a device to be used
B |Device failure. Replace the device and register its hardware hash in Autopilot; it self-provisions with no data migration. Where the replacement has previously run a self-deploying deployment, clear its Autopilot record first (Technical Configuration Document, 4.6.2)
B |Site failure. Devices at other sites are unaffected; there is no shared component between sites other than the Microsoft and Zscaler services
B |Tenant-level failure. A Participant Kiosk continues to run its current configuration and remains usable for local document work; policy and application changes resume when the service returns
B |App Control recovery. The enforced policy is signed, so deleting an Intune profile does not remove it. A replacement policy signed with the same certificate and set to audit mode is produced and held in escrow before the enforced policy deploys. Applying it is the documented rollback
