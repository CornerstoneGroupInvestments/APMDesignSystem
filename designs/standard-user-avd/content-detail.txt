H1 |1. Introduction
H2 |1.1 Purpose
P |This document is the detail design for the APM Standard User Standard Operating Environment delivered on Azure Virtual Desktop. It replaces the existing Windows 10 Azure Virtual Desktop environment, and converts the production Windows 11 thick client SOE into a virtual desktop channel and specifies the AVD components, the Intune policy inheritance and the network design required to run it.
P |The SOE is one build with two channels. A user works on a physical Windows 11 laptop, or on a Windows 11 Enterprise multi-session host reached through the Windows App. The hardening standard, the Intune policy stack and the compliance position are the same in both. Every control that cannot apply to a multi-session host is listed in [[7]] with the control that replaces it.
P |Configuration values, console paths and build steps are not in this document. They are specified in the companion Technical Configuration Document.

H1 |2. Overview
P |APM operates a Windows 11 thick client SOE. Devices are hybrid joined: domain members in on-premises Active Directory, synchronised to Microsoft Entra ID, with ADFS providing federated authentication. They are Intune managed and hardened under the APM Windows SOE Hardening Standard V3.0, which carries 748 controls across 11 Intune policies, benchmarked against the ASD Windows Hardening Guidelines, the Microsoft Windows 11 v24H2 security baseline and the Microsoft Edge security baseline v139. App Control for Business runs in enforcement.
P |ADFS is being decommissioned. This design takes no dependency on it: session hosts are Entra ID joined.
P |Where the two channels diverge, the divergence is named. There are four: the device join type, SOE update by image replacement in place of in-place patching, the five varied controls in [[7]], and the multi-session application requirements in [[5.4]]. Everything else is common.
P |This design delivers the same SOE on Azure Virtual Desktop. Session hosts run Windows 11 Enterprise multi-session on a pooled host pool in Australia East, orchestrated by Nerdio Manager for Enterprise. Hosts are Entra ID joined and Intune enrolled, so the same 11 policy objects govern them. User state persists in FSLogix profile containers on Azure Files Premium.
P |The solution deploys into the APM Azure landing zone. It requires a new /23 address allocation and a spoke virtual network peered to the Australia East hub. Egress follows the landing zone forced tunnel pattern through the hub Palo Alto next-generation firewalls. Web traffic is filtered per user by Zscaler Client Connector for VDI and a Cloud Connector in the spoke; the firewalls do not forward spoke traffic to Zscaler. No public IP address, inbound port or internet-facing endpoint is created in the spoke.
P |Australia East is the only region in scope. Nerdio audit events, session host diagnostics, host pool connection events, Azure Files transactions and firewall logs land in the Australia East Log Analytics workspaces and Microsoft Sentinel.

H1 |3. Business Architecture
H2 |3.2 Business Reference architecture
P |The staff endpoint is a managed Windows 11 laptop. It carries a fixed cost per seat, a procurement and build lead time per starter, and a physical dependency: the device has to be in the user's hands.
P |This design adds a second delivery channel for the same desktop. The user reaches a hardened Windows 11 desktop from an APM laptop or from a personal device running the Windows App. The desktop, its policy set and its data handling are identical in both cases.
P |Three business outcomes follow. A starter or a short-term worker is productive without a device build. A user whose laptop fails keeps working from any compatible endpoint. Staff work from a personal device without APM data being stored on it.
P |The personas placed on AVD in the first release are contact centre and shared-desk staff, short-term and seasonal staff, and staff working from a personal device. Field staff who work offline stay on the laptop channel.

P |**Identity and access.** Session hosts are Entra ID joined. There is no hybrid join, no Active Directory Domain Services membership and no ADFS dependency in the session host path. The thick client fleet remains hybrid joined and federated by ADFS, which is being decommissioned. Staff accounts themselves are unchanged. They remain hybrid identities, synchronised from on-premises Active Directory to Entra ID, and they authenticate to Entra ID with multi-factor authentication (A-09).
P |**Separability.** Nothing in the session host path requires on-premises Active Directory or ADFS. The session host holds no domain membership and needs no line of sight to a domain controller. The one residual link is the user identity: the profile store authenticates a hybrid identity through Microsoft Entra Kerberos, so a move of staff accounts to cloud only re-opens that decision and nothing else. The position element by element is in [[5.4]].
P |**Conditional Access.** Three existing enforced policies apply and one policy is created ([[5.1.2]]). AllUsers_WVDApp_MFAtimeout requires multi-factor authentication to the Azure Virtual Desktop application for every user. AllUsers_AllAccess_DeviceRequired requires a compliant or hybrid joined device for every application, so an unmanaged endpoint reaches Microsoft 365 only from inside a session. CA-210 requires multi-factor authentication and a compliant device for Office 365 from a session host. CA-102 blocks sign-in from outside Australia and the corporate locations.
P |**Location restriction is inherited, not created.** CA-102 - All Users &amp; Guests - All Apps - Locations exc. P |**Exclusions, to prevent the same file being scanned twice.** A profile container is a VHDX on the profile share, mounted into the session.
