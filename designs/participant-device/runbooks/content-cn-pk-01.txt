H1 |Solution overview
P |The APM ES Participant Kiosk is a Dell desktop running Windows 11 Enterprise, Microsoft Entra ID joined and managed by Microsoft Intune. It is deployed to APM Employment Services sites for participant use.
P |The device operates under a multi-application restricted user experience. The available application set is Microsoft Edge, LibreOffice Writer, Calc and Impress, and File Explorer scoped to the Downloads and Desktop folders. No other application, and no Windows administrative interface, is reachable from the session.
P |There is no participant identity and no credential. The device authenticates automatically to a Windows-managed local account, so no username or password exists for a participant to enter and none is displayed. On restart, all session data written by the previous user is purged.
P |**CompNow performs the build.** Receive and inspect the device and record its serial number. Verify the firmware settings, where the model requires it. Install the APM image from USB, which erases the internal drive and replaces the factory operating system. Register the device in Windows Autopilot with the group tag PARTICIPANT. Initiate provisioning. Verify the outcome against the acceptance criteria in Stage 8. Then pack, label and dispatch the device, and update the asset register.
P |Everything between provisioning and the acceptance tests is automated. Once the device is registered and provisioning has begun, Intune applies the configuration, the security baseline and the application set with no operator intervention.
H1 |Critical build requirements
NUM|The **APM image** is installed from USB at Stage 3, before Autopilot registration. It carries the required Windows version, the current updates and the APM certificates, and replaces the factory operating system. Autopilot provisions on top of it and does not change the Windows version.
NUM|Registration in **Windows Autopilot** is the first action performed against APM's systems, and it must be complete before provisioning is initiated at Stage 7. No configuration, application or lockdown reaches an unregistered device. Stages 4 and 5 deliver registration.
NUM|The Autopilot group tag must read **PARTICIPANT** in upper case. The tag is the sole mechanism that assigns the kiosk deployment profile. An incorrect or absent tag results in a standard Windows desktop with no lockdown applied.
NUM|**Userless enrolment status** must read **Allowed** before provisioning is initiated at Stage 7, and before any rebuild. A device at Blocked fails during the account setup phase of provisioning.
NUM|No device is dispatched until it has been **restarted and has returned to the restricted session unattended**. Stage 8 is the acceptance test for the build.

H2 |Preparing the build USB drive
P |**APM to confirm before issue:** Two things a technician needs before assembling the kit: the exact filename of the PowerShell script that run-CreateMIREGKey.bat invokes, so its receipt and its placement on the drive can be confirmed; and the USB preparation tool. This procedure specifies Rufus 4.5 or later; confirm that is the tool CompNow is to use, since it is third-party software the build facility may not carry.
P |Done once, on a build facility workstation, not per device. One drive serves every device in the batch. Prepare a spare as well: a failed drive stops every build at the facility.
NUM|Obtain the four files listed above from APM.
NUM|Insert a USB drive of 16 GB or larger. Anything on it is erased.
NUM|Open **Rufus** on the workstation.
NUM|Under **Device**, select the USB drive. Check the drive letter and capacity match the drive inserted.
NUM|Next to **Boot selection**, choose **SELECT** and pick Windows11_25H2_PK_Updated_20260827.iso.
NUM|Set **Partition scheme** to **GPT** and **Target system** to **UEFI (non CSM)**.
NUM|Set **File system** to **FAT32**. Where Rufus warns that the Windows image file exceeds the FAT32 limit and offers to split it, accept. FAT32 is required: it boots under Secure Boot without a third-party bootloader, so Secure Boot stays enabled throughout the build.
NUM|Choose **START**. Where Rufus offers Windows customisation options, accept the defaults and choose **OK**. Confirm the warning that the drive will be erased.
NUM|Wait for Rufus to report **READY**, then close Rufus.
NUM|Open the USB drive in File Explorer. Copy the three script files to the **top level of the drive**, not into a folder.
P |**Check before use:** The top level of the drive shows get-autopilothash.bat, run-CreateMIREGKey.bat, the PowerShell script, and the Windows installation folders (sources, boot and others).
P |**Report to APM if** Rufus reports an error, or the ISO is refused as not bootable. Do not attempt to build a device from a drive that did not reach READY. Quote the message Rufus showed.

H1 |Stage 3 - Install the APM Windows image (25 to 40 minutes)
P |The APM image carries the required Windows version, the current updates and the APM certificates. It is installed from USB before Autopilot registration, so that the correct Windows version is present and the factory operating system is replaced. Autopilot provisions on top of this image and does not change the Windows version.
P |**This stage erases the internal drive.** Every existing partition is deleted, including the factory operating system. That is intended. Confirm the unit is correct, that Stage 1 is complete, and that Stage 2 is complete where it applies.
H2 |3.1 Boot from the build USB drive
NUM|Shut the device down. Hold the power button for 10 seconds where it will not shut down from the screen.
NUM|With the device off, connect the **build USB drive**.
NUM|Press the power button, then **immediately start tapping** the one-time boot menu key about once a second. This is **F12** on Dell.
NUM|From the boot menu, select the USB device listed under **UEFI Boot**. Do not select a legacy or non-UEFI entry.
P |**On screen:** Windows Setup, beginning with a language and keyboard screen.
P |Where the device boots into the factory Windows instead, the boot selection did not register. Switch off and repeat, tapping the key earlier.
P |**Report to APM if** the device reports a Secure Boot violation, or refuses the USB device as untrusted. The build USB drive must be FAT32 with GPT and UEFI (non CSM), per Prerequisites: a drive prepared as NTFS boots through a third-party bootloader that Secure Boot refuses. Re-prepare the drive. Do not disable Secure Boot.
H2 |3.2 Install the image
NUM|Work through the language and keyboard screens, then choose **Install now**.
NUM|At the installation type screen, choose **Custom: Install Windows only (advanced)**. Do not choose Upgrade.
NUM|Delete every partition listed against the internal drive. Select each in turn, choose **Delete**, then **OK** to confirm.
NUM|Continue until the internal drive shows a single entry reading **Unallocated Space**.
NUM|Select that entry and choose **Next**. Setup creates the partitions and installs the image.
P |**On screen:** An installation progress screen. The device restarts one or more times without operator input.
P |Installation takes 25 to 40 minutes depending on the device. Begin the next device at Stage 1 while this one installs.
P |**Report to APM if** Windows Setup returns an error, no internal drive is listed, or the installation does not complete. Provide a photograph of the screen and the serial number.
H2 |3.3 Stop at the out-of-box experience
NUM|Wait until the device restarts into the **out-of-box experience (OOBE)**, the first screen after installation, which requests a country or region.
NUM|**Stop there. Do not work through OOBE and do not create an account.** Autopilot completes OOBE itself at Stage 7, and an account created here breaks the self-deploying enrolment the build depends on.
NUM|Leave the build USB drive connected. Where Stage 4 applies, it runs the scripts on this drive.
P |**Report to APM if OOBE has been worked through, or an account has been created.** The device cannot be recovered by restarting it: the local account and the completed OOBE persist, and Autopilot self-deploying will not run. Rebuild the device from Stage 3, which erases the drive and clears both. Record the serial number and report it, so the Autopilot record can be checked before the rebuild.

H1 |Stage 7 - Initiate provisioning (20 to 60 minutes, unattended)
NUM|At the command prompt, enter the following.
P |Type: shutdown /r /t 0   then press Enter
NUM|The device restarts and provisioning begins. **Do not use the keyboard or mouse. Do not disconnect power or the network cable.**
P |**On screen, in this order:** The out-of-box experience briefly, then a screen headed **Device preparation** or **Setting up your device** showing a list of stages and a progress indicator. The device restarts itself once or twice during the run. Both are expected.
P |During provisioning the device joins Microsoft Entra ID, enrols in Intune, renames itself, and installs LibreOffice, the Zscaler Client Connector and the remote support client. H1 |Stage 8 - Acceptance testing (10 minutes)
P |Seven tests. All seven must pass before the device is dispatched. Record each result on the build record sheet.
P |**Any test that fails stops the device.** Do not dispatch it, do not attempt a fix, and do not move on to the next test. Report the failing test number and the serial number to APM.
H2 |Test 1 - Automatic sign-in to the restricted session
P |Allow the device to settle. The expected state is a desktop showing the APM wallpaper and a taskbar.
P |**Fail if** a sign-in screen requests a username, password or PIN. The device is configured to authenticate automatically with no operator input, so a prompt means provisioning did not complete correctly. Allow a further 30 minutes and restart once. Report to APM if the prompt persists. Do not attempt to sign in.

NUM|Open **File Explorer**.

H2 |Test 6 - Zscaler Client Connector
P |Inspect the notification area at the right of the taskbar. The Zscaler icon must be present. Hover over it and confirm it does not report a disconnected or error state.

H2 |Test 7 - Restart session purge
P |This test verifies that participant data does not persist between sessions. It is the primary control this build exists to deliver.
NUM|Confirm test.odt from Test 4 is present in the Downloads folder. **Where it is absent, stop: Test 4 did not complete. Return to Test 4 and do not record Test 7 at all.** An empty Downloads folder proves nothing if nothing was saved into it.

P |**Pass:** The document is no longer present and the Downloads folder is empty. Edge retains no history and no saved credentials.
P |**Fail if** test.odt persists after the restart. The session purge is not operating. Report to APM. **This test is void, not passed,** where test.odt was not present before the restart.
