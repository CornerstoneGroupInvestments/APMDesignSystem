ES Participant Kiosk
Efficient Deployment Guide

For APM Digital Operations and build technicians · APM Standard Operating Environment Program

What this guide is for

Ten steps build one ES Participant Kiosk. Eight of the ten take a few minutes of technician time; the other two, the Windows installation and the automatic provisioning that follows it, run for 25 to 40 minutes each with nobody watching. A batch built one device at a time therefore spends most of its day idle.

This guide sets out the ten steps in order, and the bench layout and sequencing that let one technician hold four to six devices in flight at once. The detailed per-step procedure, with every on-screen confirmation and escalation path, is CN-PK-01 Device Build Procedure. Use this guide to plan and run a batch; use CN-PK-01 when a step does not behave as described.

The six things that stop a build

  1. The device is registered in Windows Autopilot and tagged PARTICIPANT in upper case before anything else is done to it. The tag is the sole mechanism that assigns the kiosk deployment profile: an absent, lower-case or misspelt tag produces a standard Windows desktop with no lockdown, and the device has to be rebuilt.
  2. Ethernet stays disconnected through installation and the out-of-box experience, and is connected immediately before the registry key script is run at step 6. A cable connected earlier changes what the device does at the out-of-box experience.
  3. The registry key script is run at the out-of-box experience, from the command prompt opened with Shift + F10, before anything else is done to the device. OOBE is never worked through and no account is ever created.
  4. The image is installed from a UEFI USB entry in the F12 boot menu. A legacy entry produces a device that cannot provision.
  5. Zscaler, TeamViewer and LibreOffice must all three be present before the device is packed.
  6. The Wi-Fi configuration profile AU-W11-SEC-Kiosk Device Wi-Fi-P-1.0 must show as applied in Intune. Sites have no ethernet ports, so it is the device's only path to the network, and the fault is only discovered at the site.

Writing the build USB drives

15 minutes per drive

Write the APM Windows 11 25H2 image to a USB drive of 16 GB or larger, as a GPT / UEFI (non CSM) / FAT32 drive so that it boots with Secure Boot enabled. Accept the offer to split the install file where the tool warns it exceeds the FAT32 limit. Then copy the build scripts to the top level of the drive, not into a folder. Full keystrokes: CN-PK-01, Prerequisites.

APM supplies the image. Write it with Rufus, or an equivalent bootable-USB tool the build facility already carries. Prepare every drive for the batch in one sitting, from the same image file. A drive is then reused for every device it builds.

The ten steps

1 · Register the device in Autopilot and tag it PARTICIPANT

5 to 20 minutes

Nothing is done to the device until it is registered in Windows Autopilot and carries the group tag PARTICIPANT. The tag determines the configuration the device receives, and no configuration, application or lockdown reaches an unregistered device.

  1. In Intune, choose Devices, then Enrolment, then Devices under the Windows Autopilot heading.
  2. Find the device in the list by serial number. Registering and tagging the whole batch ahead of time is the preferred path, so the device should already be listed. Where it is not, capture the hardware hash on the device with Get-AutopilotHash.bat at the out-of-box experience and import it, per CN-PK-01 Stages 4 and 5. That is the manual fallback, one device at a time.
  3. Read the Group Tag column. It must read PARTICIPANT in upper case.
  4. Where it is empty, lower case or any other value, select the device, choose Edit on the right-hand panel, enter PARTICIPANT in upper case, then Save.
  5. Read the Userless enrolment status column, scrolling right if it is not visible. It must read Allowed. Where it reads Blocked, select the device and choose Unblock. Blocked is expected on any device that has previously completed a kiosk build, including returned units.
Ready to buildThe device is listed in Autopilot, Group Tag reads PARTICIPANT, and Userless enrolment status reads Allowed.
Do not start step 2 until all three are true. A device built without the tag provisions to a standard Windows desktop and has to be rebuilt from step 2, and a device left at Blocked fails during the account setup phase of provisioning, forfeiting the whole run.

Register and tag the whole batch in one sitting at the start of the day, checking each serial number off the allocation list. That takes the check off the critical path for every device that follows.

2 · Boot the Dell thin client from USB

2 minutes
  1. With the device off, connect the build USB drive, the monitor, the keyboard, the mouse and power.
  2. Press the power button, then immediately start tapping F12 about once a second until the boot menu opens.
  3. Select the USB device listed under UEFI Boot.
On screenWindows Setup, beginning with a language and keyboard screen.

Record the serial number on the record sheet while the device boots. It is on the carton label and on the device.

3 · Confirm ethernet is not connected

Immediate
No network cable is connected to the device at this point. Check the port physically before continuing. A connected cable changes what the device does at the out-of-box experience and the build cannot be recovered by unplugging it later. The cable goes in at step 6, not before.

4 · Install Windows 11 from the image

25 to 40 minutes, unattended

Work through the language and keyboard screens, choose Custom: Install Windows only (advanced), delete every partition on the internal drive until it reads a single Unallocated Space entry, then continue. The device restarts one or more times without input.

This erases the internal drive, including the factory operating system. That is intended. Delete partitions on the internal drive only. The build USB drive is also listed on this screen: deleting a partition on it destroys the build media, and the drive has to be written again before any further device can be built. Identify the internal drive by its capacity before deleting anything.

Start the next device at step 2 now. This is the longest unattended wait in the build and the largest single throughput gain available.

5 · Stop at the out-of-box experience

Immediate

Wait for the device to restart into the out-of-box experience, the first screen after installation, which asks for a language or region.

Stop there. Do not work through OOBE and do not create an account. A device that has completed OOBE, or that has an account on it, cannot be recovered by restarting. It must be rebuilt from step 2.

6 · Run the registry key script

3 minutes
  1. At the language prompt, press Shift + F10 together to open a command prompt. On some keyboards this needs Fn held as well: Shift + Fn + F10.
  2. Connect the ethernet cable now, just before running the script. The device restarts and provisions itself as soon as the script runs, and provisioning needs the network.
  3. Type the following and press Enter.
d:\Run-CreateMIRegKey.bat [Enter]

The script progresses the device through the out-of-box experience automatically and hands it to Autopilot. There is no completion message and no prompt: the device restarts itself and provisioning begins.

On screenPowerShell text scrolling past, then the device restarts on its own and starts provisioning. No further input.

Where the response is The system cannot find the path specified, the USB drive holds a different letter. Type e: then Enter, then dir, and repeat with f: and so on until the build files are listed, then run the batch file from that letter.

7 · Wait for automatic sign-in, and sync Intune

20 to 60 minutes, unattended

The device restarts, provisions itself, and signs in automatically to the restricted session. No keyboard or mouse input, and no sign-in prompt: there is no participant identity and no password on this build.

To shorten the wait, find the device in Intune by serial number and choose Sync. Repeat every few minutes rather than waiting on the device's own check-in schedule. This is the difference between a 20 minute step and a 60 minute one.

On screen at the endA desktop showing the APM wallpaper and a taskbar, reached with no input.

Work the bench in a loop while this runs: start a new device at step 2, run step 6 on any device sitting at OOBE, and press Sync on every device in flight.

Where the device sits on the same screen beyond 90 minutes, or shows an error code, stop. Photograph the screen, record the serial number and the start time, and escalate. Do not restart or wipe it.

8 · Confirm the applications are installed

5 minutes

All three must be present on the device before it is packed.

ApplicationHow to confirm
ZscalerThe Zscaler icon is in the notification area at the right of the taskbar, and hovering over it does not report a disconnected or error state.
TeamViewerPresent and running. This is the remote support path once the device is at site, so a device without it cannot be supported.
LibreOfficeWriter, Calc and Impress each open. Each is a separate application in the restricted session's allowed list, so one opening does not prove another will. Open test.odp from the USB drive in Impress if a file is wanted for the check.
Any one of the three absent stops the device. Do not pack it and do not attempt a fix. Report the serial number and which application is missing.

Where the batch is being accepted formally rather than spot-checked, run the seven acceptance tests in CN-PK-01 Stage 8 instead of this step. They cover the restricted application set, the File Explorer restriction and the restart session purge as well as the three applications above.

9 · Verify the Wi-Fi profile in Intune

3 minutes
This is the step that most often prevents a device working at site, and the only one whose failure is invisible on the device itself. APM sites have no ethernet ports, so this profile is the device's only path to the network. Without it the kiosk cannot connect at all, and there is no local way for site staff to fix it.
  1. In Intune, choose Devices, then find the device by serial number or by its name, which begins APM-PK-.
  2. Open the device and choose Device configuration.
  3. Find AU-W11-SEC-Kiosk Device Wi-Fi-P-1.0 in the profile list.
  4. Confirm the profile state reads Succeeded.
PassThe profile is listed and reads Succeeded.
Fail if the profile is absent from the list, or reads Error, Conflict or Pending. Choose Sync and allow 15 minutes. Where syncing does not resolve it, rebuild the device from step 2. Report the serial number and the state shown. Do not dispatch the device.

While the device page is open, confirm the device name begins APM-PK-. A name in any other form means the device did not receive the kiosk configuration, which is almost always an Autopilot group tag other than PARTICIPANT. See CN-PK-01 Stage 5.

10 · Pack and dispatch

5 minutes
  1. Shut the device down through Windows: Ctrl + Alt + Delete, the power icon, then Shut down.
  2. Disconnect the build monitor, keyboard, mouse and cables. These stay at the bench unless the allocation list says otherwise.
  3. Repack the device into its original carton with its power supply and all supplied accessories.
  4. Label the carton exterior with the device name and the destination site address.
  5. Place the APM site instruction sheet inside the carton, uppermost, so it is the first thing site staff see.
  6. Update the asset register: device name, serial number, destination site, status Dispatched, date.
  7. Release to the courier and record the consignment number.

Running a batch efficiently

The two long steps, the Windows installation at step 4 and the provisioning at step 7, need no attention. Everything else is minutes. So the technician's day is a loop across the bench rather than a device followed end to end.

The loop

Walk the bench in this order and repeat. Each pass takes a few minutes.

Look for
Action
Empty bay
Start the next device off the batch list, already registered and tagged at step 1: steps 2, 3, 4. Then leave it.
At OOBE
Run step 6, the registry key script. Then leave it.
Provisioning
Press Sync in Intune. Nothing else.
Signed in
Steps 8, 9, 10. This frees the bay.

The bench holds one device per bay. Four bays is the point at which one technician is busy without queueing; six is workable where the Intune workstation sits at the bench rather than across the room.

What to fix before scaling up

  1. Prove one device end to end first, at a new facility or after any image change, before starting a batch. A network or image fault found on device one costs an hour; found on device twelve it costs a day.
  2. Register and tag the whole batch before the first device is booted. The step 1 checks are quick in bulk and slow one at a time, and a missed tag is only discovered at the end of a 90 minute build.
  3. Write every drive from the same image file. The date in the image filename is its version. Confirm it against the most recent APM notification before a batch, and re-write every drive when the image changes.
  4. Keep the Intune device list open all day. Steps 7 and 9 both use it, and the Sync at step 7 is the single largest time saving in the build.
  5. Record as you go, not at the end. The record sheet is the evidence the device was checked. A sheet filled in from memory at dispatch is worth nothing when a device fails at site.
