ES Participant Kiosk
Device Build Procedure

For CompNow build technicians · APM Standard Operating Environment Program

Solution overview

The APM ES Participant Kiosk is a Dell desktop running Windows 11 Enterprise, Microsoft Entra ID joined and managed by Microsoft Intune. It is deployed to APM Employment Services sites for participant use.

The device operates under a multi-application restricted user experience. The available application set is Microsoft Edge, LibreOffice Writer, Calc and Impress, and File Explorer scoped to the Downloads and Desktop folders. No other application, and no Windows administrative interface, is reachable from the session.

There is no participant identity and no credential. The device authenticates automatically to a Windows-managed local account, so no username or password exists for a participant to enter and none is displayed. On restart, all session data written by the previous user is purged.

CompNow performs the build. Receive and inspect the device and record its serial number. Verify the firmware settings, where the model requires it. Install the APM image from USB, which erases the internal drive and replaces the factory operating system. Register the device in Windows Autopilot with the group tag PARTICIPANT. Initiate provisioning. Verify the outcome against the acceptance criteria in Stage 8. Then pack, label and dispatch the device, and update the asset register.

Everything between provisioning and the acceptance tests is automated. Once the device is registered and provisioning has begun, Intune applies the configuration, the security baseline and the application set with no operator intervention.

Critical build requirements

  1. The APM image is installed from USB at Stage 3, before Autopilot registration. It carries the required Windows version, the current updates and the APM certificates, and replaces the factory operating system. Autopilot provisions on top of it and does not change the Windows version.
  2. Registration in Windows Autopilot is the first action performed against APM's systems, and it must be complete before provisioning is initiated at Stage 7. No configuration, application or lockdown reaches an unregistered device. Stages 4 and 5 deliver registration.
  3. The Autopilot group tag must read PARTICIPANT in upper case. The tag is the sole mechanism that assigns the kiosk deployment profile. An incorrect or absent tag results in a standard Windows desktop with no lockdown applied.
  4. Userless enrolment status must read Allowed before provisioning is initiated at Stage 7, and before any rebuild. A device at Blocked fails during the account setup phase of provisioning.
  5. No device is dispatched until it has been restarted and has returned to the restricted session unattended. Stage 8 is the acceptance test for the build.

Preparing the build USB drive

APM to confirm before issueTwo things a technician needs before assembling the kit: the exact filename of the PowerShell script that run-CreateMIREGKey.bat invokes, so its receipt and its placement on the drive can be confirmed; and the USB preparation tool. This procedure specifies Rufus 4.5 or later; confirm that is the tool CompNow is to use, since it is third-party software the build facility may not carry.

Done once, on a build facility workstation, not per device. One drive serves every device in the batch. Prepare a spare as well: a failed drive stops every build at the facility.

  1. Obtain the four files listed above from APM.
  2. Insert a USB drive of 16 GB or larger. Anything on it is erased.
  3. Open Rufus on the workstation.
  4. Under Device, select the USB drive. Check the drive letter and capacity match the drive inserted.
  5. Next to Boot selection, choose SELECT and pick Windows11_25H2_PK_Updated_20260827.iso.
  6. Set Partition scheme to GPT and Target system to UEFI (non CSM).
  7. Set File system to FAT32. Where Rufus warns that the Windows image file exceeds the FAT32 limit and offers to split it, accept. FAT32 is required: it boots under Secure Boot without a third-party bootloader, so Secure Boot stays enabled throughout the build.
  8. Choose START. Where Rufus offers Windows customisation options, accept the defaults and choose OK. Confirm the warning that the drive will be erased.
  9. Wait for Rufus to report READY, then close Rufus.
  10. Open the USB drive in File Explorer. Copy the three script files to the top level of the drive, not into a folder.
Check before useThe top level of the drive shows get-autopilothash.bat, run-CreateMIREGKey.bat, the PowerShell script, and the Windows installation folders (sources, boot and others).
Report to APM if Rufus reports an error, or the ISO is refused as not bootable. Do not attempt to build a device from a drive that did not reach READY. Quote the message Rufus showed.

Stage 1 · Receipt and power-on inspection

3 minutes
  1. Open the carton. Remove the device, the power supply and all accessories. Retain the carton and all packaging for repacking at Stage 9.
  2. Record the serial number on the build record sheet. It is printed on the carton label and on the device.
  3. Connect the monitor, keyboard, mouse, ethernet cable and power.
  4. Press the power button once.
On screenThe Dell logo, followed by the factory operating system starting, or a first-run screen. Either state is expected. The factory operating system is replaced at Stage 3, so its state does not matter.
Report to APM if the device does not power on, shows physical damage, or halts on an error before the Dell logo. Do not attempt repair and do not proceed. Set the device aside, photograph it, record it as DOA on the build record sheet and in the asset register, and follow the faulty-goods return process.

Record in the asset register: serial number, model, destination site, status In build.

Stage 2 · Firmware verification

4 minutes, only where required

The device model APM has purchased for this use case ships with the correct firmware configuration, so no firmware change is expected and this stage is not performed on those units. Where any other model is used, verify the three settings below before proceeding.

  1. Switch the device off. Hold the power button for 10 seconds if it will not shut down.
  2. Press the power button, then immediately start tapping the firmware entry key about once a second until the firmware screen opens. This is F2 on Dell; Delete and F10 are common on other vendors. Where Windows starts instead, switch off and repeat, tapping earlier.
  3. Locate and confirm the three settings in the table below. The paths given are for Dell firmware. On another vendor's firmware the settings carry the same or similar names under equivalent menus, so locate each by name rather than by path.
SettingMust beDell menu path
TPM 2.0 / Security DeviceOn and EnabledSecurity, or Security > TPM 2.0 Security
Boot modeUEFI, not LegacyBoot Configuration
Secure BootEnabledBoot Configuration > Secure Boot
  1. Where a setting was changed, choose Apply Changes, then OK.
  2. Choose Exit. The device restarts.
Report to APM if TPM 2.0 cannot be enabled, or reports a state other than Enabled. Set the device aside, record the serial number, and follow the faulty-goods process.

Stage 3 · Install the APM Windows image

25 to 40 minutes

The APM image carries the required Windows version, the current updates and the APM certificates. It is installed from USB before Autopilot registration, so that the correct Windows version is present and the factory operating system is replaced. Autopilot provisions on top of this image and does not change the Windows version.

This stage erases the internal drive. Every existing partition is deleted, including the factory operating system. That is intended. Confirm the unit is correct, that Stage 1 is complete, and that Stage 2 is complete where it applies.

3.1 Boot from the build USB drive

  1. Shut the device down. Hold the power button for 10 seconds where it will not shut down from the screen.
  2. With the device off, connect the build USB drive.
  3. Press the power button, then immediately start tapping the one-time boot menu key about once a second. This is F12 on Dell.
  4. From the boot menu, select the USB device listed under UEFI Boot. Do not select a legacy or non-UEFI entry.
On screenWindows Setup, beginning with a language and keyboard screen.

Where the device boots into the factory Windows instead, the boot selection did not register. Switch off and repeat, tapping the key earlier.

Report to APM if the device reports a Secure Boot violation, or refuses the USB device as untrusted. The build USB drive must be FAT32 with GPT and UEFI (non CSM), per Prerequisites: a drive prepared as NTFS boots through a third-party bootloader that Secure Boot refuses. Re-prepare the drive. Do not disable Secure Boot.

3.2 Install the image

  1. Work through the language and keyboard screens, then choose Install now.
  2. At the installation type screen, choose Custom: Install Windows only (advanced). Do not choose Upgrade.
  3. Delete every partition listed against the internal drive. Select each in turn, choose Delete, then OK to confirm.
  4. Continue until the internal drive shows a single entry reading Unallocated Space.
  5. Select that entry and choose Next. Setup creates the partitions and installs the image.
On screenAn installation progress screen. The device restarts one or more times without operator input.

Installation takes 25 to 40 minutes depending on the device. Begin the next device at Stage 1 while this one installs.

Report to APM if Windows Setup returns an error, no internal drive is listed, or the installation does not complete. Provide a photograph of the screen and the serial number.

3.3 Stop at the out-of-box experience

  1. Wait until the device restarts into the out-of-box experience (OOBE), the first screen after installation, which requests a country or region.
  2. Stop there. Do not work through OOBE and do not create an account. Autopilot completes OOBE itself at Stage 7, and an account created here breaks the self-deploying enrolment the build depends on.
  3. Leave the build USB drive connected. Where Stage 4 applies, it runs the scripts on this drive.
Report to APM if OOBE has been worked through, or an account has been created. The device cannot be recovered by restarting it: the local account and the completed OOBE persist, and Autopilot self-deploying will not run. Rebuild the device from Stage 3, which erases the drive and clears both. Record the serial number and report it, so the Autopilot record can be checked before the rebuild.

Stage 4 · Hardware hash capture

5 minutes

The hardware hash is the device identifier Autopilot uses to match a device to its deployment profile. APM requires it before provisioning can begin.

Omit this stage where APM has confirmed the batch is already registered (Dell can register devices at the point of manufacture). Where registration is unconfirmed, capture the hash. A duplicate capture has no adverse effect.

4.1 Open a command prompt on the device

  1. The device is at the out-of-box experience from Stage 3. Where it has since been switched off, power it on and wait for that screen.
  2. Confirm the build USB drive is still connected from Stage 3. Where it was removed, reconnect it.
  3. Press Shift + F10 together.
On screenA black console window ending in a prompt similar to X:\windows\system32>. Commands are entered at this prompt.

If nothing happens, try Shift + Fn + F10. On some keyboards the function keys need Fn held as well.

4.2 Switch to the build USB drive

Type the following. Press Enter at the end of each line.

d: [Enter]
dir [Enter]
On screenA directory listing of the USB drive. Both get-autopilothash.bat and run-CreateMIREGKey.bat appear in the list.

Where the response is The system cannot find the drive specified, the USB drive holds a different letter. Enter e: then Enter, then f:, and so on, running dir at each until the build files are listed.

4.3 Run the hash capture file

get-autopilothash.bat [Enter]

The batch file opens PowerShell and collects the hash. Do not interrupt it. Capture takes two to three minutes and the console may appear inactive during that period.

APM to confirm before issueThe message get-autopilothash.bat returns on completion, the name of the file it writes, and its location. Also whether the batch file writes the CSV as UTF-8: a file produced by redirecting PowerShell console output is UTF-16, which Intune rejects as having incorrect column headings.
  1. When it has finished, check the file was created. Type dir then Enter and look for a new .csv file.
  2. Confirm the file is UTF-8 encoded. Open it in Notepad and read the encoding shown at the bottom right of the window. Intune rejects a file saved as UTF-16 and reports it as having incorrect column headings, even where the headings are correct.
  3. Where it reads UTF-16 LE or Unicode, choose File then Save as, set Encoding to UTF-8, and save over the file.
  4. Leave the USB drive connected. It is required again at Stage 6.
  5. Do not restart the device yet.
Report to APM if the console returns errors, closes immediately, or no .csv file is written. Provide a photograph of the screen and the serial number.

Stage 5 · Autopilot registration and group tag

5 to 20 minutes

Where Stage 4 was performed, CompNow imports the hardware hash to the APM tenant directly, at 5.1. The group tag applied at import determines the configuration the device receives.

5.2 and 5.3 are performed on every device, by either path. A device registered at manufacture arrives without a group tag more often than one imported here, so 5.2 matters most on exactly the path that skips 5.1.

APM to confirm before issueThe sign-in account CompNow uses for the import, and the permissions it carries.

5.1 Import the hash to the APM tenant

Omit 5.1 where Stage 4 was omitted, that is where the batch was registered at manufacture. Confirm the device already appears in the Autopilot devices list by its serial number, then continue at 5.2.

Report to APM if a device from a batch registered at manufacture does not appear in the Autopilot devices list at all. It cannot provision until it is registered. Provide the serial number and do not proceed to Stage 6.
  1. On the build workstation, open intune.microsoft.com and sign in with the account APM has provided.
  2. In the left menu choose Devices.
  3. Choose Enrolment.
  4. Choose Devices under the Windows Autopilot heading.
  5. Choose Import at the top of the page.
  6. Choose Select a file, select the .csv file, then choose Import.
  7. Wait for the import to complete. This can take up to 15 minutes. Choose Sync, then Refresh, until the device appears in the list.
Report to APM if the import returns an error, or the device does not appear in the list after 30 minutes. Provide the serial number and the error shown. Do not proceed to Stage 6: an unregistered device cannot provision.

5.2 Verify the group tag on every device

Verify the tag on every device, by either path. Locate the device in the Autopilot devices list by serial number and read the Group Tag column.

On the same device row, read the Userless enrolment status column. Scroll right if the column is not visible.

Do not omit this check. A device left at Blocked begins provisioning normally and fails during the account setup phase, forfeiting the full provisioning run. Verify the status before Stage 7, and again before any rebuild.

Stage 6 · Run the registry key script

2 minutes
APM to confirm before issueThe function and purpose of run-CreateMIREGKey.bat, stated in one sentence, and the message it returns on success. This procedure sequences the script here, after Autopilot registration and before provisioning; confirm that placement, and whether devices registered at manufacture require it.

Return to the device. A command prompt at the USB drive is required. Where Stage 4 was omitted, or the prompt has since closed, perform steps 4.1 and 4.2 to open one.

run-CreateMIREGKey.bat [Enter]

The batch file opens PowerShell, sets the execution policy for the session, then runs the script. No operator input is required.

On screenPowerShell text scrolling past, then it returns to the command prompt.
Report to APM if the console returns errors, or reports that script execution is disabled on the system. Provide a photograph of the screen and the serial number.

Stage 7 · Initiate provisioning

20 to 60 minutes, unattended
  1. At the command prompt, enter the following.
shutdown /r /t 0 [Enter]
  1. The device restarts and provisioning begins. Do not use the keyboard or mouse. Do not disconnect power or the network cable.
On screen, in this orderThe out-of-box experience briefly, then a screen headed Device preparation or Setting up your device showing a list of stages and a progress indicator. The device restarts itself once or twice during the run. Both are expected.

During provisioning the device joins Microsoft Entra ID, enrols in Intune, renames itself, and installs LibreOffice, the Zscaler Client Connector and the remote support client. The Enrolment Status Page blocks device use until all required applications have installed, so the device cannot be used before the build completes.

Begin the next device at Stage 1 while this one provisions. Multiple devices can be built concurrently.

Where the device remains on the same screen beyond 90 minutes, or displays an error code, stop and report to APM. Provide a photograph of the screen, the serial number and the provisioning start time. Do not restart or wipe the device: APM requires it in its current state for diagnosis.

Stage 8 · Acceptance testing

10 minutes

Seven tests. All seven must pass before the device is dispatched. Record each result on the build record sheet.

Any test that fails stops the device. Do not dispatch it, do not attempt a fix, and do not move on to the next test. Report the failing test number and the serial number to APM.

Test 1 · Automatic sign-in to the restricted session

Allow the device to settle. The expected state is a desktop showing the APM wallpaper and a taskbar.

Fail if a sign-in screen requests a username, password or PIN. The device is configured to authenticate automatically with no operator input, so a prompt means provisioning did not complete correctly. Allow a further 30 minutes and restart once. Report to APM if the prompt persists. Do not attempt to sign in.

Test 2 · Application set

Inspect the taskbar and the Start menu against the following.

Must be presentMust not be present
Microsoft EdgeMicrosoft Word, Excel or PowerPoint
LibreOffice WriterSettings
LibreOffice CalcCommand Prompt or PowerShell
LibreOffice ImpressMicrosoft Store
File ExplorerAnything else at all
Fail if any application in the right-hand column is present, or any in the left-hand column is absent. The restricted user experience has not applied. Report to APM, naming the applications found.

Test 3 · Microsoft Edge and managed favourites

  1. Open Microsoft Edge.
  2. Confirm a page loads rather than an error.
  3. Confirm the favourites bar displays the APM managed favourites.
  4. Open one favourite and confirm the page loads.
Fail if no page loads, the favourites bar is absent, or the favourites are not the APM set. Report to APM, stating which of the three applies.

Test 4 · LibreOffice

All three applications are opened. Each is a separate executable with its own entry in the restricted session's allowed list, so one launching does not prove another will.

  1. Open LibreOffice Writer.
  2. Enter several words of text.
  3. Save the document. Name it test.odt and confirm the location offered is Downloads.
  4. Close Writer.
  5. Open LibreOffice Calc. Confirm a spreadsheet window opens, then close it. Do not save.
  6. Open LibreOffice Impress. Confirm a presentation window opens, then close it. Do not save.
  7. Open File Explorer and confirm test.odt is in Downloads before continuing.

Leave test.odt in place. Tests 5 and 7 both use it, and Test 7 cannot be run without it.

Fail if any of the following. Report to APM, naming which.
  • Writer, Calc or Impress does not open, or opens and then closes on its own. Name which of the three.
  • test.odt is not in Downloads after saving.
Launch failure is the most frequently observed fault on this build.

Test 5 · File Explorer namespace restriction

  1. Open File Explorer.
  2. Confirm Downloads and Desktop are present, and that test.odt from Test 4 is in Downloads.
  3. Click the address bar at the top of the window, type C:\ and press Enter.
  4. Click the address bar again, type C:\Windows and press Enter.
  5. Confirm neither opens. The expected result is that the location is refused or nothing happens.
Fail if either address opens, or Downloads and Desktop are absent, or test.odt is not in Downloads. An address that opens means the namespace restriction has not applied. Report to APM, naming what was reachable.

Test 6 · Zscaler Client Connector

Inspect the notification area at the right of the taskbar. The Zscaler icon must be present. Hover over it and confirm it does not report a disconnected or error state.

Fail if the icon is absent, or reports a disconnected or error state. Report to APM, quoting the state shown.

Test 7 · Restart session purge

This test verifies that participant data does not persist between sessions. It is the primary control this build exists to deliver.

  1. Confirm test.odt from Test 4 is present in the Downloads folder. Where it is absent, stop: Test 4 did not complete. Return to Test 4 and do not record Test 7 at all. An empty Downloads folder proves nothing if nothing was saved into it.
  2. Restart the device. Press Ctrl + Alt + Delete, then choose the power icon, then Restart. Where that is blocked, hold the power button for 10 seconds and switch it back on.
  3. Wait for the device to return to the restricted session unattended, with no sign-in prompt.
  4. Open File Explorer and inspect Downloads.
PassThe document is no longer present and the Downloads folder is empty. Edge retains no history and no saved credentials.
Fail if test.odt persists after the restart. The session purge is not operating. Report to APM.
This test is void, not passed, where test.odt was not present before the restart.

Stage 9 · Packaging, labelling and asset record

5 minutes
  1. Record the device name. Open File Explorer, right-click This PC and choose Properties, or read it from the Autopilot devices list in Intune. The name begins APM-PK- followed by six characters.
Do not proceed where the device name does not begin APM-PK-. The device has not received the kiosk configuration, which in almost all cases indicates an incorrect group tag at Stage 5. Correct the tag at Stage 5, then rebuild the device from Stage 3.
  1. Shut the device down through Windows. Ctrl + Alt + Delete, power icon, Shut down.
  2. Disconnect the build monitor, keyboard, mouse and cables. These remain at the build facility unless the allocation list specifies otherwise.
  3. Repack the device into its original carton with its power supply and all supplied accessories.
  4. Label the carton exterior with the device name and the destination site address.
  5. Place the APM site instruction sheet inside the carton, uppermost. APM supplies it, and it covers unboxing, connecting and power-on for site staff, so it must be the first thing seen when the carton is opened.
  6. Update the asset register: device name, serial number, status Dispatched, date, destination site.
  7. Release to the courier. Record the consignment number in the asset register.

Provide APM with the serial number, the stage reached, and a photograph of the screen. These three items allow APM to diagnose without further contact.
