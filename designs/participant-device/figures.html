Participant Kiosk provisioning

1 · Device preparation - Deployment Team

Wipe, install Windows 11 Enterprise, register the hardware hash, and assign the device to its Entra location group for the destination site.

2 · First boot at the site

The device connects to the hidden APM-KIOSK SSID during OOBE and the Autopilot registration is detected.

3 · Self-deploying tenant join

Autopilot joins the device to the APM corporate tenant by TPM-backed attestation. No user signs in, and no user account is created.

4 · Intune enrolment

The device consumes an Intune device licence and lands in sg-dyn-dvc-cdg-participant-kiosk, named APM-PK-[RRR] by the Autopilot template.

5 · Policy and application delivery

Security baseline, Assigned Access, Edge hardening, idle restart, purge scripts, App Control, LAPS, LibreOffice, Zscaler and TeamViewer.

6 · Enrolment Status Page and rename

The ESP blocks until every required application and policy has applied. The rename job appends the site digits: APM-PK-1231001.

7 · Automatic logon

The device restarts and Windows signs in the Assigned Access account. No credential is entered, displayed or held by APM.

Session lifecycle and data purge

1 · Boot and auto sign-in

Startup purge removes any profile that survived a power loss. Edge starts with an ephemeral profile.

3 · Idle warning

At nine minutes a full-screen warning counts down the final 60 seconds. Any input dismisses it.

5 · Clean session

The device returns to a fresh participant session, ready for the next person.

2 · Session in use

Documents in the local profile or on the participant's USB. Nothing is written to a cloud store.

4 · Restart at ten minutes

The shutdown script deletes the profile, Public Downloads, temp and the print spool.

Access control model

Participant Kiosk - device identity only

Entra-joined device object, Intune managed. The session runs as a Windows-managed local account. No user signs in to Windows, and no corporate identity exists on the device.

Layer 1 · Identity - CA-APM-PK-BlockCorporateAccess

All users, all cloud apps, filtered on the fleet enrolment profile. Break-glass accounts excluded.

Layer 2 · Device - Edge URL blocklist

Navigation to the Microsoft 365 and Azure surface is refused before any credential is entered.

Layer 3 · Network - Zscaler URL filtering

The same destinations blocked at the proxy, covering any client that is not the managed Edge.

SOE Hardening Standard inheritance model

APM Windows SOE Hardening Standard V3.0

748 controls across 11 Intune policies. Benchmarked against the ASD Windows Hardening Guidelines, the Microsoft Windows 11 v24H2 baseline and the Microsoft Edge security baseline v139. Governs every APM Windows endpoint, including this fleet.

Inherited unchanged

OS baseline, ASR rules, BitLocker on the fixed drive, Edge baseline, developer-tools restriction.

Excluded - 3 controls

Removable storage deny-all; removable-disk deny write; BitLocker required on removable media. Scoped to SG-APM-ParticipantDevice-Devices only.

Fleet-additional

App Control fleet variant, Assigned Access with auto-logon, logon lockdown, 600s restart, profile purge, Store off, LibreOffice hardening.

COMPENSATING CONTROLS

Already in the standard

AutoPlay and AutoRun off all drives; Defender scans removable drives; ASR blocks untrusted and unsigned processes running from USB.

Added by this design

App Control enforced with script enforcement ON; File Explorer scoped to removable drives; no shell, command prompt or Task Manager.

Participant Kiosk posture

Assessed on the same basis as a staff device, with three named removable-media exclusions carrying documented compensating controls, accepted by APM Cyber Security in the RFFR Statement of Applicability and reviewed annually with the standard.
