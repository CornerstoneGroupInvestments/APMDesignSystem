Per-device credential pipeline

1 · Autopilot enrolment

The device provisions through the kiosk Autopilot profile and lands in SG-APM-Autopilot-Kiosk-Devices (Autopilot group tag).

2 · Account Creation runbook - Azure Automation

Graph POST /users creates kiosk-<serial>@apmkiosk.net.au; F3 assigned by group-based licensing on SG-APM-Kiosk-Users.

3 · Key Vault secret

ANIMAL-noun passphrase generated (e.g. PANTHER-blanket, min. 14 characters) and written to auea-kv-apm-kiosk-001 as secret kiosk-<serial>.

4 · Credential Proxy - Function App

Reads the secret with its managed identity and renders the lock-screen PNG server-side.

5 · Proactive Remediation - hourly

Presents the SCEP device certificate over mTLS, compares version.txt and fetches the image only on change.

6 · Lock screen

Displays the device UPN and current passphrase - the secret is never exposed to the device as text.

7 · 12-month rotation runbook

Re-enters the pipeline at the Key Vault step; the next remediation cycle refreshes the lock screen.

Kiosk device provisioning flow

1 · Device preparation

Unpack, full wipe, install Windows 11 Enterprise, confirm TPM 2.0 and UEFI, register the hardware hash under the kiosk Autopilot group tag.

2 · First boot at the site

Device connects to the APM-KIOSK SSID during OOBE; Autopilot registration is detected.

3 · Self-deploying tenant join

Autopilot self-deploying mode joins the device to the apmkiosk.net.au tenant by TPM-backed attestation - no user signs in during OOBE.

4 · Intune enrolment and account provisioning

Device lands in SG-APM-Autopilot-Kiosk-Devices; the Account Creation runbook provisions kiosk-<serial> and its Key Vault secret.

5 · Policy application

Intune applies the security baseline, multi-app Assigned Access, Edge hardening, idle sign-out, logon lockdown and profile cleanup.

6 · Enrolment Status Page and rename

ESP blocks until all required apps and policies apply; the rename script sets KI-[SITECODE]-[SERIAL].

7 · Kiosk shell ready

Device reboots into the kiosk shell; the lock screen shows the device UPN, passphrase and data-wipe notice.

Conditional Access and network control flow

1 · Site network

Meraki default-deny egress, TCP 443 only, FQDN/IP allow-list; Palo Alto inspection; Zscaler ZIA category filtering and SSL inspection.

2 · Platform - CA-APM-Kiosk-BlockNonWindows

Windows only, evaluated independently of device filters.

3 · Device identity - CA-APM-Kiosk-BlockNonKioskDevices

Device must carry enrolment profile APM-Kiosk-SelfDeploying.

4 · Device health - RequireCompliantDevice

CA-APM-Kiosk policy: Entra-joined and Intune-compliant; 12-hour sign-in frequency.

5 · Protocol - CA-APM-Kiosk-BlockLegacyAuth

Modern authentication only - IMAP, POP, SMTP AUTH and ActiveSync closed.

6 · Authentication flow - CA-APM-Kiosk-BlockAuthFlows

No device code flow, no authentication transfer.

7 · Location - CA-APM-Kiosk-BlockNonAU

Sign-in must present an Australian IP; kiosk traffic always egresses via Zscaler’s Australian datacentres.

8 · Application - CA-APM-Kiosk-WebOnlyOffice

Office for the web and SharePoint/OneDrive only; all other cloud apps denied.

9 · Device OS - Logon Lockdown

"Allow log on locally" restricted to this device’s own kiosk user and local administrators - each credential bound to one physical kiosk.

SOE Hardening Standard inheritance model

APM Windows SOE Hardening Standard V3.0

748 controls across 11 Intune policies. Benchmarked against the ASD Windows Hardening Guidelines, the Microsoft Windows 11 v24H2 baseline and the Microsoft Edge security baseline v139. Governs every APM Windows endpoint, including the kiosk.

Inherited unchanged

OS baseline, ASR rules, BitLocker (fixed drive), Edge baseline, developer-tools restriction, compliance policy.

Excluded - 3 controls

Removable storage deny-all; removable-disk deny write; BitLocker required on removable media. Scoped to SG-APM-Kiosk-Devices only.

Kiosk-additional

App Control kiosk variant, Assigned Access, Logon Lockdown, 600s sign-out, profile deletion, Store off, OneDrive purge.

COMPENSATING CONTROLS

Already in the standard

AutoPlay and AutoRun off all drives; Defender scans removable drives; ASR blocks untrusted and unsigned processes running from USB.

Added by the kiosk

App Control enforced with script enforcement ON; File Explorer scoped to removable drives; no shell, command prompt or Task Manager.

Kiosk device posture

Assessed on the same basis as a staff device, with three named removable-media exclusions carrying documented compensating controls, accepted by APM Cyber Security in the kiosk RFFR Statement of Applicability and reviewed annually with the standard.
