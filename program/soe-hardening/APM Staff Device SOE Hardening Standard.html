Introduction

This document details the security hardening implemented on APM's Windows 11 Standard Operating Environment (SOE) for staff devices. The standard is based on the Australian Signals Directorate (ASD) Hardening Microsoft Windows 11 workstations guidance and the corresponding Microsoft security baselines, and is intended to be read in conjunction with them.

APM has chosen to assess the recommended High and Medium priority controls and implement them unless there is an impact to business operations by doing so. These controls are referenced by their control area below and mapped to the relevant ASD Information Security Manual (ISM) controls. Where APM has chosen not to implement, or to vary from, a control in the ASD guidance, this has been noted in this standard.

Hardening is delivered and continuously enforced through Microsoft Intune configuration and compliance policies, with identity controls in Microsoft Entra ID and threat protection through Microsoft Defender for Endpoint. The compliance driver is APM's obligation under the Right Fit For Risk (RFFR) accreditation (ISO 27001 aligned, mapped to the ASD ISM). This standard applies to all APM-managed Windows 11 staff devices that make up the SOE; server operating systems and directory infrastructure are out of scope and are addressed under separate server standards.

The current assessed compliance position against ASD and Microsoft guidance, the Intune policies that deliver this baseline, and the outstanding items requiring action are set out in Compliance summary and Gap remediation plan.

High Priority Controls

SOE hardening

The SOE is reviewed and updated at least annually. SOE images provided by third parties are scanned for malicious content and configurations before being used.

Authentication hardening

Passphrases used for single-factor authentication are a minimum of 20 characters with complexity, ideally six random words, and cannot be used to authenticate to multiple different systems. Multi-factor authentication is enforced through Microsoft Entra ID Conditional Access. Service accounts are managed and are not used for interactive sign-in.

Application hardening

Application control is implemented on all staff workstations to restrict the execution of executables, software libraries, scripts and installers to an approved set, using cryptographic hash, publisher certificate and path rules. Microsoft's latest recommended block rules are applied to prevent application-control bypasses. Other than privileged users performing specific administrative activities, users cannot disable, bypass or be exempted from application control, and failed execution attempts are logged with the file name, timestamp and user. Applications that allow macros, such as Microsoft Office, are configured to disable all macros with notification. Applications installed onto an SOE device must pass the Software Approval process, which validates the security posture of the vendor and the configuration of the application.

Application versions and patches

All SOE devices are onboarded to Microsoft Intune and scanned by Microsoft Defender for Endpoint to confirm application and operating-system versions are current and patched. Vulnerabilities are addressed in a timeframe appropriate to the severity of the vulnerability.

Local Administrator Accounts

The built-in local administrator account is managed by Windows LAPS, with passwords automatically rotated and escrowed to Microsoft Entra ID. UAC restrictions are applied to local accounts on network sign-in. Local administrator access is restricted to accounts required for device management.

Operating System Patching

Windows Update for Business manages quality and feature updates centrally through update rings configured in Microsoft Intune.

Password Policy

APM enforces a password policy through Microsoft Entra ID password protection; the policy settings exceed those specified in the ASD guidance.

Operating System Architecture

APM's entire fleet is built on x64 system architecture on Windows 11 (24H2); no device images are based on an alternative architecture. The latest or N-1 version of the operating system is used.

Secure Boot

Secure Boot is set by the hardware vendor at the factory and applied as a step during the build process, and is verified by Intune compliance policy.

Medium Priority Controls

Account Lockout Policy

Account lockout is configured through Microsoft Entra ID smart lockout; the lockout settings exceed those specified in the ASD guidance.

Audit Event Management

Advanced audit policy is configured to capture account management, sign-in and sign-out, process creation (including the command line), policy change, system integrity and object-access events. Event-log sizes are set appropriately and events are forwarded to Microsoft Defender for Endpoint for central retention and analysis.

BIOS and UEFI passwords

BIOS and UEFI passwords are set by the hardware vendor at the factory, and Intune compliance checks verify that the password has been set.

Bridging Networks

Installation and configuration of a network bridge is prohibited, and connection to non-authenticated networks while connected to a managed network is restricted.

Variation: the minimise-simultaneous-connections value differs from ASD guidance — see Gap remediation plan.

File and Print Sharing

Ad-hoc peer file and print sharing is restricted.

Safe Mode

Non-administrators are restricted from using Safe Mode, which is protected by BitLocker.

Security Policies

Microsoft consumer experiences are turned off; shell-protocol protected mode is enabled; game recording and broadcasting is disabled; downloading of RSS enclosures is prevented; and default permissions of internal system objects are strengthened.

Compliance summary

The hardening configuration has been reassessed against current ASD and Microsoft guidance, with the result recorded setting-by-setting in the companion Intune Compliance Worksheet. Approximately 700+ recommended settings were validated against APM's applied Intune policies and platform defaults, using the ASD Hardening Microsoft Windows 11 workstations guidance, the Microsoft Windows security baseline for Intune (Windows 24H2), the ASD Office and macro hardening guidance, the Microsoft Office baseline (December 2025), and the ASD Microsoft Edge hardening guidance.

Of the 708 settings assessed, the position against ASD-specific guidance is:

Assessment outcome (ASD guidance)SettingsShare
Compliant with ASD guidance47767%
Non-compliant — decision pending396%
No ASD guidance / not applicable19127%
Planned1<1%

After reconciliation against Microsoft guidance where ASD offers none, the overall position is 591 compliant, 7 residual non-compliances escalated for decision, 98 settings with no specific guidance (informational or secure-by-default), and 12 not applicable. All 39 ASD non-compliances are assessed at Low residual risk; 28 of the 39 carry a High business-impact rating, which is why they have not yet been remediated.
