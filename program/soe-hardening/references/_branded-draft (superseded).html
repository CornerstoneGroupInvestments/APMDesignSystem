Version 3.0 rebases the standard from the legacy on-premises model to APM's modern-managed environment. 1 Introduction & purpose

This document defines the security hardening applied to APM's Windows 11 Standard Operating Environment (SOE). It is the authoritative control standard for staff end-user devices and the reference used to demonstrate hardening compliance at audit.

The standard is based on the Australian Signals Directorate (ASD) Hardening Microsoft Windows 11 workstations guidance and the corresponding Microsoft security baselines, and is intended to be read in conjunction with them. APM assesses the recommended controls and implements them unless there is an unacceptable impact to business operations; where APM varies from or does not implement a control, this is recorded with a risk rationale (see §9 and §10).

Hardening is delivered and continuously enforced through Microsoft Intune configuration and compliance policies, with identity controls in Microsoft Entra ID and threat protection through Microsoft Defender for Endpoint. This replaces the Group Policy delivery model described in earlier versions of this standard. The compliance driver is APM's obligation under the Right Fit For Risk (RFFR) accreditation (ISO 27001 aligned, mapped to the ASD Information Security Manual).

2 Scope

This standard applies to all APM-managed Windows 11 end-user devices, across the following use cases. All use cases inherit the same baseline hardening; differences are expressed as documented exceptions (see §5).

Use caseDescriptionHardening position
Standard devicesGeneral staff laptops and desktops.Full baseline stack applied.
Developer devicesEngineering devices requiring developer tooling.Baseline + Edge Developer exception; App Control in audit mode.
Job Seeker / Employment ServicesParticipant-facing and field devices.Baseline + USB and BitLocker exceptions.
Privileged EUC devicesAdministrative / privileged-access workstations.Baseline + USB boot and BitLocker exceptions.
Out of scope — Windows 10
A small number of Job Seeker / Employment Services devices remain on Windows 10; a redesign for these is underway within APM. Windows 10 devices are out of scope for this standard and are tracked separately for migration. This standard does not carry forward any Windows 10-specific or Windows Phone / mobile-device settings (e.g. simple-password, mobile minimum-OS and mobile-unlock settings), which have no effect on Windows 11 devices.

Also out of scope: server operating systems and on-premises directory infrastructure (AD DS / AD CS / AD FS). Server hardening and the extension of Application Control for Business to core servers are tracked under separate server standards (referenced in §9).

A Appendix — Security control review summary

This appendix consolidates the security-control review (previously two separate summary decks) into a single audit-facing overview. It restates the review approach, compliance position and the high-implementation-risk items by area.

Review approach

Hardening guidance was taken from ASD and Microsoft (ASD Windows hardening guidelines, ASD Blueprint for Secure Cloud, ASD Office macro guidance, the Windows MDM security baseline for Intune — Windows 24H2, and the Microsoft Office baseline). The approach validated that 700+ recommended settings are applied to APM devices either by policy or by secure default.
