1. Introduction
1.1 Purpose
The Design Definition document outlines the proposed target-state of the solution, specifically the application or service, the technology or process, and the integration requirements. Design Definition typically does not contain the detailed specification of how each piece works, rather it defines what technology parts are used and how they interact.
The Design Definition document aims to:
•Outline the Key Architectural Principles to guide the implementation of the solution, as well as the Architectural Objectives for the Program;
•Identify the need for change in ICT capabilities as classified by the business architecture capability model and align capability to the selected solution components to implement the capabilities;
•Define the scope boundaries for the program (including impacted solution components) and relationships and interdependencies to in-flight and planned programs; and
•Describe the proposed target-state architecture to a sufficient level of detail to provide input into project scope and business case.
1.2 Document Scope
The Design Definition document summarises the conceptual target state or TO-BE architecture. The document identifies the need for change in capabilities as classified by the business architecture capability model. It aligns capability to the selected solution components to implement the capabilities. Each solution component identified to implement capability will be elaborated in detailed design documents.
