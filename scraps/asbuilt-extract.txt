<Heading1> 1. Purpose and Use
<Heading2> 1.1 Purpose
This document is the as-built record of the ES Participant Kiosk Solution. It names every object the solution consists of, the value each object carries, and the administration console each one is configured in, so that the solution can be operated, audited and maintained from this document alone.
It is written at solution level. Where a full build procedure, a script listing or a click path is needed, this document names the object and points to the document that holds it. It does not repeat those documents.
<Heading2> 1.2 Audience
•  Digital Operations - day to day operation, monitoring and the routine maintenance tasks in 16. Routine Maintenance
•  APM Solution Engineer - configuration changes to any object listed here
•  APM Cyber Security - control assurance, App Control policy signing, Conditional Access state, RFFR evidence
•  APM Network Management - the site network, Wi-Fi and egress configuration in 12. Network Configuration
•  Digital Transformation and Architecture - change assessment against 17. Change Control
<Heading2> 1.3 Scope
In scope. Every Entra ID, Intune, Windows, network and Zscaler object created or altered for the Participant Kiosk fleet, its configured values, the console each is held in, the routine maintenance the solution requires, and the items that may not be changed without a change record.
Out of scope. Build procedures (Technical Configuration Document and the two runbooks), design rationale and the Decision Register (Detail Design Document), and the estate Windows baseline this fleet inherits from (APM Windows SOE Hardening Standard V3.0).

<Heading1> 2. Solution Summary
<Heading2> 2.1 What is deployed
A physical Dell device in an APM Employment Services site, for participant use. It runs Windows 11 Enterprise under multi-app Assigned Access and signs itself in to a local account that no person holds a credential for. There is no participant identity, no credential to issue and nothing displayed for a participant to type.
The device is Entra ID joined and managed entirely by Intune. It is provisioned by Windows Autopilot in self-deploying mode on top of an APM image installed at the build facility. Applications are installed locally: Microsoft Edge, LibreOffice Writer, Calc and Impress, and File Explorer scoped to the Downloads folder and removable drives. Microsoft 365 is blocked from the device at three independent layers.
Every session ends at a restart, and the restart destroys the session. The device restarts after ten minutes without input, and the purge runs at logon and at logoff.

<Heading2> 4.2 Conditional Access
One policy. It denies rather than grants, and it targets hardware rather than identity.
[TABLE 9 rows]
  | Field | Value
  | Name | CA-107 - All Users &amp; Guests - All Apps - Participant Kiosk Devices - Block
  | Users, include | All users
  | Users, exclude | The two tenant emergency access accounts
  | Target resources | All cloud apps
  | Conditions, filter for devices | Include devices where: device.trustType -eq "AzureADJoined" -and device.enrollmentProfileName -eq "CDG W11 Autopilot SelfDeploying"
  | Grant | Block access
  | Session | Not configured
  | State | On, enforced before national rollout. Report-only during the pilot
A Participant Kiosk is Entra ID joined and compliant, so it satisfies both tenant grant policies, AllUsers_AllAccess_DeviceRequired and AllUsers_AllAccess_MFAorDeviceRequired, and satisfies the second without a multi-factor prompt. Neither grant policy is modified and neither carries a kiosk exclusion: in Conditional Access an applicable block overrides a grant.
Ten further tenant policies evaluate a user principal and are never evaluated for this fleet. None is modified and none needs an exclusion. The full policy by policy disposition, the six build steps and the five verification tests are in the Conditional Access as-built record, APM_AsBuilt_Participant_Kiosk_Conditional_Access_V1.0.
Guidance    The device filter matches the enrolment profile name as a literal string, and that name is CDG W11 Autopilot SelfDeploying: spaces, no hyphens, no version suffix. It does not follow the CDG-W11-[class]-[name]-[env]-[version] convention, and it is not the name this fleet's other objects carry. Renaming the Autopilot deployment profile silently stops this policy matching, and the fleet then satisfies both corporate grants with nothing blocking it. Treat any change to that profile name as a change to CA-107.

<Heading2> 7.1 Logon lockdown
The intended value was Administrators plus this device's session account. Assigned Access account names are per device, and the setting takes a single static value list with no wildcard support, so the account cannot be named.
[TABLE 6 rows]
  | Setting | Value
  | Profile name | CDG-W11-SEC-Logon Lockdown-P-1.0
  | Setting | Allow Local Log On, under User Rights. Not under Local Policies Security Options, where it was first looked for
  | Value | *S-1-5-113 and *S-1-5-32-544
  | *S-1-5-113 | Local account. Covers the session account without naming it
  | *S-1-5-32-544 | Administrators. Covers APM-PKAdmin (4.3 Device records and local administrator)
S-1-5-113 admits any local account on the device, not only the session account. On this fleet that is the session account and APM-PKAdmin, and no third local account is created by anything in this document. Narrowing it to the session account alone needs the per-device user right set by script, which is recorded as open item 2 in 18. Known Constraints and Open Items.
The Assigned Access configuration is delivered twice. The custom OMA-URI profile CDG-W11-CFG-Assigned Access XML-P-1.0 was built and assigned, and it writes the same CSP node the session account remediation writes (8.1 Session account, automatic logon and Assigned Access). The profile carries a static XML file, so its Account element cannot name a per-device account; the remediation renders the account name and applies it per device. Both target ./Vendor/MSFT/AssignedAccess/Configuration, and the last writer wins. This is open item 14 in 18. Known Constraints and Open Items.
<Heading1> 8. The Participant Session
Three Intune remediation pairs deliver the participant session. All three are configured under Devices &gt; Scripts and remediations, all run as SYSTEM in 64-bit with the signature check on, and all three are assigned to sg-dyn-dvc-cdg-participant-kiosk on a daily schedule plus the first enrolment check-in.
[TABLE 4 rows]
  | Object | Version | Marker value | What it owns
  | CDG-W11-REM-Kiosk Session Account-P-1.0 | - | - | The session account, automatic logon and the Assigned Access configuration (8.1 Session account, automatic logon and Assigned Access)
  | CDG-W11-REM-Idle Restart-P-1.0 | 4.0 | IdleRestartVersion | Inactivity lock and the restart that ends the session (8.2 Inactivity restart)
  | CDG-W11-REM-Session Cleanup-P-1.0 | 2.0 | SessionCleanupVersion | Destruction of participant data at every session boundary (8.3 Session cleanup)
The idle restart and the session cleanup each write a version marker to HKLM\SOFTWARE\APM\ParticipantKiosk once, and only once, every asserted item has been re-verified. Detection reads that marker as its last check, so a device that half-converged reports as drift rather than as compliant.
Guidance    All three were Win32 applications in an earlier build. The remediation model replaced them because a Win32 application installs once and is never re-evaluated: drift on a device that has already reported success is invisible. A remediation pair re-asserts every item daily, and each detection emits exactly one line naming what drifted.

<Heading2> 8.1 Session account, automatic logon and Assigned Access
[TABLE 9 rows]
  | Setting | Value
  | Object name | CDG-W11-REM-Kiosk Session Account-P-1.0

  | Account properties | Full name equals the account name, description "APM Participant Kiosk - managed, do not modify", account never expires, password never expires, may not change its own password, enabled

  | Automatic logon | AutoAdminLogon = 1, DefaultUserName = the account. DefaultPassword, DefaultDomainName and AutoLogonCount are removed on every run

Detection fails the device, and calls the remediation, on any one of these. The account missing, disabled, renamed in its display name, carrying password expiry, or permitted to change its own password. Membership of Administrators. Automatic logon not configured, or a cleartext DefaultPassword or a DefaultDomainName value present. Assigned Access not applied, not naming this device's account, or still holding the literal [SERIAL] placeholder, which means a configuration profile has overwritten the CSP node.
A password the account can change is fatal rather than untidy: a changed password breaks automatic logon permanently, because the LSA secret no longer matches and no person holds the new value.
<Heading3> 8.1.1 Application allow-list in the restricted session
The allow-list is rendered per device, because it names the session account, and the LibreOffice dependency paths are discovered on the device at run time rather than assumed.
[TABLE 6 rows]
  | Group | Entries
  | Microsoft Edge | msedge.exe and msedge_proxy.exe under Program Files (x86), plus the Edge application user model ID Microsoft.MicrosoftEdge.Stable_8wekyb3d8bbwe!App
  | LibreOffice | swriter.exe, scalc.exe, simpress.exe, soffice.exe and soffice.bin, plus the discovered dependencies LanguageToolLO.dll, select.pyd and _socket.pyd
  | Supporting applications | Zscaler ZSATray.exe, TeamViewer.exe
  | Accessibility | Narrator.exe, Magnify.exe, osk.exe, VoiceAccess.exe

<Heading2> 8.2 Inactivity restart
The session ends at a restart, and the restart is triggered by the workstation locking rather than by a process polling for idle time. [TABLE 9 rows]
  | Setting | Value
  | Object name | CDG-W11-REM-Idle Restart-P-1.0, version 4.0

[TABLE 8 rows]

Guidance    All four screen-saver values are REG_SZ. Winlogon reads them as strings, so a REG_DWORD is a silent no-op: the value appears set, and the screen saver never starts. Detection reads the value type through reg.exe rather than trusting the data alone.
Two of the seven rows above are the ones a reviewer should check first. Remediation is ordered so that a partial run cannot present as a working device: it clears the version marker first, resolves the session account from the profile directory on disk and stops outright if it cannot, and refuses to touch the scheduled task until it has an account name to filter on. Superseded and actively removed. Scheduled task APM-PK-IdleWatchdog, the files Watch-KioskIdle.bat, Watch-KioskIdle.ps1, idle-state.txt, idle-armed.txt, idle-pending.txt and idle-debug.txt, and the IdleWatchdogVersion marker. Remediation deletes all of them, and detection reports the old task's presence as drift, because two mechanisms restarting the same device on two different signals is a fault in itself.

<Heading1> 9. Time and Time Zone
A kiosk with a wrong clock puts a wrong timestamp on every document a participant saves, and a clock far enough out fails TLS, which presents as a device that can no longer reach anything. The time zone and the clock are two separate settings with two separate mechanisms, and this section records both.
[TABLE 4 rows]

  | CDG-W11-SCR-Fallback Time Zone-P-1.0 | Platform script, once per device | A starting time zone, so a device never begins life on a wildly wrong clock while location resolution is pending (9.2 Fallback time zone)
  | CDG-W11-TST-Time and Time Zone Readiness-P-1.0 | Pilot verification tool, not an Intune object | A read-only readiness report, and the exercise of the two egress endpoints that produces the real deny list (9.4 Readiness verification)

<Heading3> 9.1.1 Service start values

[TABLE 4 rows]

<Heading3> 9.1.3 Clock synchronisation
[TABLE 6 rows]
  | Setting | Value | Where
  | MaxPosPhaseCorrection (DWORD) | 172800 | HKLM\SYSTEM\CurrentControlSet\Services\W32Time\Config
  | MaxNegPhaseCorrection (DWORD) | 172800 | As above
  | w32time stop trigger | Removed | sc.exe triggerinfo w32time delete
  | Configuration reload | w32tm /config /update | Run after the values are written
  | Resynchronisation | w32tm /resync /rediscover | Redetects network configuration and rediscovers sources
172800 seconds is 48 hours. The default ceiling on a device that is not AD domain-joined is 54000 seconds, 15 hours, and a sample outside the ceiling is discarded rather than applied. A kiosk that has been switched off for weeks, or that has a flat CMOS battery, lands outside 15 hours and never heals. 48 hours covers that case while still bounding what the device will accept from a reachable NTP source.
The service control manager holds a stop trigger on w32time for the condition not domain joined, so setting the service to Automatic is not enough on its own: the service is started and then stopped again. Removing the trigger is the documented workaround for that case.
A failed clock synchronisation is reported and is not treated as a remediation failure: the configuration is correct and the fault is on the network. Detection keeps reporting it until it clears.

<Heading2> 9.3 Egress requirements
Two destinations are required, and neither is a web destination reachable through the proxy path in 12.4 Zscaler Client Connector.
[TABLE 3 rows]
  | Destination | Protocol | Note
  | time.windows.com | UDP 123 | UDP 123 does not traverse a web proxy. This is a firewall rule, never a Zscaler URL exception. Every NTP sample timing out means UDP 123 is blocked
  | inference.location.live.net | TCP 443 | The only Location endpoint Microsoft documents for Windows 11. The port is not stated in the documentation and is inferred from the protocol
lfsvc runs as a machine service, so a proxy that requires user authentication has no token to authenticate with and location resolution fails. The system-wide WinHTTP proxy is what applies, not a user proxy setting.
TLS inspection of the location endpoint is visible in the certificate issuer: a public issuer means the session is not being decrypted, and an APM or Zscaler issuer means it is.
<Heading2> 9.4 Readiness verification
CDG-W11-TST-Time and Time Zone Readiness-P-1.0, script TestTimeAndTimeZoneReadiness.ps1, is read-only and is not an Intune object. It is run in an elevated session on one device before anything in this section is assigned to the fleet, and again on any device that reports the wrong zone. Its output is saved with the pilot evidence.
It reports the host and language mode, all three service start values and live states, the w32time triggers, the location gates, every conflicting policy in 9.1.4 Conflicts the detection names but does not fix, the current zone, the phase correction ceiling, and the w32time source, status and configuration. It then exercises both endpoints in 9.3 Egress requirements: a five-sample w32tm stripchart against time.windows.com, and DNS resolution, a TCP 443 test and a certificate issuer check against inference.location.live.net. It closes with the Windows Time operational log, the location log channels present on the build, and the procedure for clearing a stale lfsvc location cache.
A device whose clock is correct but whose zone is wrong has either had location resolution blocked, or is serving a stale cached location fix. The lfsvc cache at %ProgramData%\Microsoft\Windows\LfSvc\Cache has been observed pinning a device to the wrong country. Clearing it is stop lfsvc, delete the cache folder, start lfsvc.

<Heading1> 11. Application Control
The fleet runs two App Control policies: a base policy duplicated from the estate enforced baseline, and a supplemental policy that carries the fleet's application rules. Both are assigned to every kiosk.
[TABLE 4 rows]
  | Policy | Role | Assignment | Origin
  | APM-WIN-SEC-ACfB Enforced Baseline_ES Kiosks-P-1.0 | Base policy | All kiosks | Duplicated from APM-WIN-SEC-ACfB Enforced Baseline-P-1.0
  | APM-WIN-SEC-ACfB Enforced Supp ES Kiosks Basic Apps A-P-1.0 | Supplemental policy | All kiosks | Created for this fleet
  | APM-W11-SEC-ACfB Exclusion-P | Exclusion | Kiosk device group added as a member | Existing estate object
Every application rule change for this fleet is made on the supplemental policy. The base policy is a duplicate of an estate object: changing it diverges the two copies, and that divergence is not visible from either policy's own view.
A base policy accepts a supplemental only when it carries Enabled:Allow Supplemental Policies. That option is what makes this model work, and it also means the base policy's allow-list can be extended by any supplemental policy deployed to the device, not only by this one.
Both policies use the estate naming prefix APM-WIN-SEC- rather than the fleet prefix CDG-W11-, because the base policy is a copy of an estate object and the supplemental extends it. The base policy name separates its scope with an underscore, APM-WIN-SEC-ACfB Enforced Baseline_ES Kiosks-P-1.0, which is the name as built.
How the fleet is kept off the estate baseline. The kiosk device group is added to the App Control policy APM-W11-SEC-ACfB Exclusion-P, which is the estate mechanism for carving a device set out of the normal baseline. Membership of that policy is what stops the estate baseline reaching a kiosk, so it is a configuration item in its own right and not a side effect of the group.
The fleet is not excluded from App Control. It runs the base policy and the supplemental above instead of the estate baseline.
Guidance    Removing the kiosk group from APM-W11-SEC-ACfB Exclusion-P puts the estate enforced baseline back onto every kiosk, on top of the base policy and supplemental. Two enforced policies on one device intersect: a binary must satisfy both, so the effective allow-list becomes the narrower of the two and applications the fleet depends on can stop launching with nothing in either policy's own view to explain it.
The exclusion policy carries the estate prefix APM-W11-SEC-, while the base and supplemental policies carry APM-WIN-SEC-. Both prefixes are in use, and the names above are the strings as built.
