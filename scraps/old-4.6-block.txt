H2 |4.6 Build Sequence - Step-by-Step Configuration Order
P |Every configuration change in this document, in the order a technician builds it. Steps 1-4 in Phase 1 are prerequisites for every later phase (DEP-001, DEP-002).
H3 |4.6.1 Phase 1 - Entra ID foundation (build first, nothing else can be assigned without these)
NUM|**Entra admin centre > Groups > New group.** Create sg-dyn-dvc-cdg-participant-kiosk-autopilot (device, dynamic membership rule: device.devicePhysicalIds -any (_ -eq "[OrderID]:PARTICIPANT")). Full detail: 11.2.4
NUM|**Entra admin centre > Groups > New group.** Create sg-dyn-dvc-cdg-participant-kiosk (device, dynamic membership rule: device name starts with APM-PK-). Full detail: 11.2.4
NUM|**Entra admin centre > Groups > New group.** Create sg-stc-dvc-cdg-participant-kiosk-ring1 (device, assigned membership, ~10 devices: staging lab plus 1-2 low-traffic sites). Full detail: 11.2.4
NUM|**Apply the corporate assignment exclusion register before any device enrols** - exclude sg-dyn-dvc-cdg-participant-kiosk from every corporate Wi-Fi/VPN/certificate profile, Conditional Access grant policy, Edge configuration profile, PowerShell platform script, compliance policy and the estate App Control policy assignment. Full register: 4.5
H3 |4.6.2 Phase 2 - Autopilot and enrolment
NUM|**Register hardware hashes.** Obtain the hardware hash for each device from CompNow (device prep partner) as a CSV, or have Dell register the devices directly to the tenant at the factory (OEM direct registration) if that agreement is in place - confirm which applies before build. Each device's Group Tag field in the CSV/registration must be set to `PARTICIPANT` so it lands in sg-dyn-dvc-cdg-participant-kiosk-autopilot automatically on import (11.2.4)
NUM|**Intune admin centre > Devices > Enrol devices > Windows Autopilot deployment program devices > Import.** Upload the CSV if hashes were not registered directly by Dell/CompNow. Confirm each row shows Group Tag = PARTICIPANT after import, and that the devices sync into sg-dyn-dvc-cdg-participant-kiosk-autopilot (Entra admin centre > Groups > the group > Members) within a few minutes
NUM|**Intune admin centre > Devices > Enrol devices > Deployment Profiles > Create profile > Windows PC.** Name it CDG-W11-CFG-Autopilot Self-Deploying-P-1.0. On the **Basics** tab: enter the name and description
NUM|**Out-of-box experience (OOBE) tab, in order top to bottom:** Deployment mode = **Self-Deploying (Preview or GA, per current tenant release)**; Join type = **Microsoft Entra joined** (self-deploying is not supported for Microsoft Entra hybrid joined devices); Microsoft Software License Terms = **Hide**; Privacy settings = **Hide**; Hide change account options = **Hide**; User account type = **Standard** (irrelevant for self-deploying, no user account is created, but leave at the default rather than Administrator); Allow pre-provisioned deployment = **No** (this fleet uses self-deploying directly, not White Glove/pre-provisioning); Language (Region) = set to the fleet's locale (e.g. English (Australia)); Automatically configure keyboard = **Yes**; Apply device name template = **No** (naming is Autopilot-assigned per 5.1.5 in the DDD, no template needed)
NUM|**Assignments tab.** Assign to sg-dyn-dvc-cdg-participant-kiosk-autopilot. Select Save
NUM|**Intune admin centre > Devices > Enrol devices > Enrollment Status Page > Create.** Name it CDG-W11-CFG-Kiosk ESP-P-1.0. **Settings tab, in order:** Show app and profile configuration progress = **Yes**; Show an error when installation takes longer than specified number of minutes = **Yes**, set to a value that comfortably exceeds the time to apply every profile and app in Phases 4-8 (start with 60 minutes and tune on pilot); Show custom message when time limit or error occurs = **Yes**, with wording pointing to the Deployment Team escalation path, since no participant or end user will see this screen unattended; Turn on log collection and diagnostics page for authorised users = **Yes**; Only show page to devices provisioned by Autopilot = **Yes**; Block device use until required apps and profiles are installed = **Yes** (this is what prevents the device reaching a desktop before Assigned Access and every lockdown profile has landed); Allow users to reset device if installation error occurs = **No** (no user is present to action this); Allow users to use device if an error occurs = **No** (fail-secure, per R-05 - a device that cannot complete provisioning must not reach a usable desktop); Block device use until these required apps are installed = select every Win32 app in Phase 6 (LibreOffice, Zscaler Client Connector, TeamViewer) plus the Assigned Access XML and lockdown profiles from Phase 5, so provisioning cannot complete without them
NUM|**Assignments tab.** Assign the ESP profile to sg-dyn-dvc-cdg-participant-kiosk-autopilot (same scope as the deployment profile)
NUM|**Verify TPM 2.0 attestation reachability.** Self-deploying mode requires the device to reach Microsoft's TPM attestation endpoints during OOBE, over the site network before the Meraki egress allow-list in 6.1.6 is fully built - confirm these endpoints are reachable on the staging/lab network used for Phase 2-3, not only on the production APM-KIOSK VLAN
H3 |4.6.3 Phase 3 - Compliance and access control (report-only)
NUM|**Intune admin centre > Devices > Compliance policies > Create policy > Platform: Windows 10 and later > Profile type: Templates.** Name it CDG-W11-COM-Participant Kiosk-P-1.0. **Compliance settings > Device Health tab:** BitLocker = **Require**; Secure Boot = **Require**. **Device Health tab, Microsoft Defender Antimalware section:** Microsoft Defender Antimalware = **Require**; Microsoft Defender Antimalware security intelligence up-to-date = **Require**; Real-time protection = **Require**; Antispyware = **Require**. **System Security tab:** Firewall = **Require**; Trusted Platform Module (TPM) = **Require**. **Device Properties tab:** Minimum OS version = pin to the validated Windows 11 Enterprise feature version (5.2.5 in the DDD). **Actions for noncompliance tab:** add action **Mark device noncompliant** with schedule **0 days** (immediately), and add a second action **Send email to specified admins** (or the existing Digital Operations alert integration) at the same 0-day schedule
NUM|**Assignments tab.** Assign to sg-dyn-dvc-cdg-participant-kiosk. Select Next, then Create
NUM|**Entra admin centre > Protection > Conditional Access > Create new policy.** Name it CA-107 - All Users &amp; Guests - All Apps - Participant Kiosk Devices - Block. **Users tab:** Include = **All users**; Exclude = the two emergency access accounts. **Target resources tab:** Cloud apps > Include = **All cloud apps**. **Conditions tab > Filter for devices:** Configure = **Yes**; Rule syntax: `device.trustType -eq "AzureADJoined" -and device.enrollmentProfileName -eq "CDG-W11-CFG-Autopilot Self-Deploying-P-1.0"`. **Grant tab:** select **Block access**. **Session tab:** leave unconfigured (n/a). **Enable policy:** set to **Report-only**. Select Create. Do not add sg-dyn-dvc-cdg-participant-kiosk or -autopilot to the Users or Devices condition anywhere in this policy - it targets by the device filter above, not by group (11.4.2.1)
H3 |4.6.4 Phase 4 - Wi-Fi and network (coordinate with the network team / Stratus)
NUM|**Meraki dashboard > Network-wide > Configure > General**, or the site template if VLAN 73 is managed centrally. Re-purpose/confirm VLAN 73 named APM-KIOSK. **Wireless > Configure > SSIDs.** Rename/configure the SSID to APM-KIOSK, set **Visibility = Hidden**. **Wireless > Configure > Access control**, on the APM-KIOSK SSID: Association requirements = **WPA2/WPA3-Enterprise with my RADIUS server** (802.1X/EAP-TLS), point at the existing APM RADIUS/NPS or Entra-integrated certificate validation service used for EAP-TLS elsewhere in the estate - no pre-shared key is configured anywhere on this SSID (DR-020)
NUM|**Meraki dashboard > Security &amp; SD-WAN > Configure > Firewall** (or the equivalent site firewall page for a standalone MX). Set the default outbound rule at the bottom of the rule list to **Deny any/any** for the APM-KIOSK VLAN, then add explicit **Allow** rules above it, in order, for: Entra ID/Intune endpoints, Windows Update/Delivery Optimization, Defender for Endpoint, the Intune content delivery network, and the Zscaler service edge (full FQDN/IP list: 6.1.6). Add the Windows Update/Delivery Optimization allow-list entries from 6.1.6 as additional Allow rules above the deny
NUM|**Meraki dashboard > Network-wide > Configure > Traffic shaping** (or SSID-level bandwidth limit on the wireless page). Set a per-SSID/per-VLAN bandwidth limit of **20 Mbps** for APM-KIOSK
NUM|**Confirm active and enforced (not just configured) at every site**, per DR-019 - open the live Firewall/Security page per site and confirm the rule set shows as applied, then attempt a blocked-destination connection from a test device on-site (test T-24) rather than trusting the dashboard configuration alone
NUM|**Intune admin centre > Devices > Configuration profiles > Create > Windows 10 and later > Templates > Trusted certificate.** Import the root/issuing CA certificate for the EAP-TLS device certificate, assign to sg-dyn-dvc-cdg-participant-kiosk
NUM|**Same console > Create > Templates > SCEP certificate** (or PKCS, per whichever certificate infrastructure APM's existing EAP-TLS deployments use - confirm with the network/PKI team before build). Configure the certificate template, key usage (Client Authentication), and validity period set to outlast the device's operational life (R-09 - no rotation exists in this design). Assign to sg-dyn-dvc-cdg-participant-kiosk
NUM|**Same console > Create > Templates > Wi-Fi.** Configure SSID = APM-KIOSK, Connect automatically = **Yes**, Security type = **WPA2/WPA3-Enterprise**, EAP type = **EAP-TLS**, Authentication method = **Certificate**, and select the SCEP/PKCS certificate profile above as the client certificate source. Assign to sg-dyn-dvc-cdg-participant-kiosk
H3 |4.6.5 Phase 5 - Device lockdown profiles (build in this order - each depends on the account/session model existing first)
NUM|**Intune admin centre > Devices > Windows > Configuration profiles > Create > Windows 10 and later > Templates > Custom.** Name it CDG-W11-CFG-Assigned Access XML-P-1.0. Add OMA-URI row: OMA-URI `./Vendor/MSFT/AssignedAccess/Configuration`, Data type **String (XML file)**, upload/paste the full Assigned Access configuration XML - breadcrumbs and complete XML in Appendix A. Assign to sg-dyn-dvc-cdg-participant-kiosk. This profile and the CDG-W11-REM-Kiosk Session Account-P-1.0 remediation pair below work together: the remediation creates the Kiosk-[SERIAL] account and substitutes it into the XML's Account element via the WMI bridge; this profile carries the multi-app lockdown itself
NUM|**Intune admin centre > Devices > Scripts and remediations > Remediations > Create.** Name it CDG-W11-REM-Kiosk Session Account-P-1.0. **Settings tab:** Detection script file = `Detect-KioskSessionAccount.ps1`; Remediation script file = `Remediate-KioskSessionAccount.ps1` (both from `designs/participant-device/config/`, both signed with the APM code-signing certificate - SOE-02, 12.7.2); Run this script using the logged-on credentials = **No** (runs as SYSTEM); Enforce script signature check = **Yes**; Run script in 64-bit PowerShell = **Yes**. **Assignments tab:** assign to sg-dyn-dvc-cdg-participant-kiosk, schedule = **Daily**, and additionally trigger at enrolment via the device's first check-in
NUM|**Intune admin centre > Devices > Configuration profiles > Create > Windows 10 and later > Settings catalog.** Name it CDG-W11-SEC-Logon Lockdown-P-1.0. Search the catalog for **"Allow log on locally"** under **Local Policies Security Options**, set the value list to **Administrators** and **Kiosk-[SERIAL]** only (the literal account name is a placeholder resolved per device by the remediation above - if the Settings Catalog control requires a literal SID/name at creation time, deliver this specific setting via the signed remediation script instead, applying the local security policy directly, and note this as a build-time decision on the pilot). Assign to sg-dyn-dvc-cdg-participant-kiosk
NUM|**Intune admin centre > Devices > Scripts and remediations > Platform scripts > Add > Windows 10 and later.** Name it CDG-W11-REM-Idle Restart-P-1.0. Upload the signed idle-watchdog script (registers a scheduled task that runs as the interactive user, warns at 9 minutes, restarts at 10 minutes/600 seconds of no input). **Script settings:** Run this script using the logged-on credentials = **Yes** (the watchdog itself runs interactively; the task registration step may still require a SYSTEM-run installer script - confirm the split at packaging time); Enforce script signature check = **Yes**. Assign to sg-dyn-dvc-cdg-participant-kiosk
NUM|**Intune admin centre > Devices > Configuration profiles > Create > Windows 10 and later > Settings catalog** for the ADMX component: search **"Delete user profiles older than a specified number of days on system restart"** under **Windows Components > User Profiles**, set to **0 days**. **Plus Intune admin centre > Devices > Scripts and remediations > Platform scripts** for the shutdown-script component: upload the signed shutdown purge script (Win32_UserProfile deletion, Downloads/Temp/print-spool clear), Run using logged-on credentials = **No** (SYSTEM), registered to run at shutdown. Name both CDG-W11-REM-Profile Purge-P-1.0 and assign both to sg-dyn-dvc-cdg-participant-kiosk
